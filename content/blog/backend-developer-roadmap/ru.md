## Порядок обучения

Backend-разработчик отвечает за то, что пользователь не видит: данные, бизнес-логику, API, безопасность и работу сервера. Учить это лучше в такой последовательности:

1. **Язык программирования** и его экосистема.
2. **Базы данных** и SQL.
3. **API**: HTTP, REST, обработка ошибок.
4. **Аутентификация и авторизация.**
5. **Тестирование.**
6. **Основы деплоя**: Linux, Docker, переменные окружения, логи.

Каждый этап заканчивается **проектом-вехой**: не сертификатом, а работающим кодом, который можно показать на собеседовании.

## Шаг 1. Язык

Выберите один язык, востребованный в вакансиях вашего региона: например, Python, JavaScript (Node.js), Go, Java, C# или PHP. Важно не «лучший язык», а глубина.

Что освоить:

- синтаксис, типы данных, функции, ООП или модульность;
- работу с файлами, исключениями, коллекциями;
- пакетный менеджер и структуру проекта;
- основы Git.

**Веха:** консольная утилита, например парсер CSV-файла с отчетом в консоли и обработкой некорректных строк.

## Шаг 2. Базы данных

- **Реляционная модель**: таблицы, ключи, связи один-ко-многим и многие-ко-многим.
- **SQL**: `SELECT`, `JOIN`, `GROUP BY`, подзапросы, транзакции.
- **Индексы**: зачем нужны и почему не стоит ставить их везде.
- **Миграции** и работа через ORM или query builder.

```sql
SELECT u.name, COUNT(o.id) AS orders
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
GROUP BY u.name
ORDER BY orders DESC;
```

**Веха:** спроектированная схема для небольшого магазина или библиотеки с миграциями и тестовыми данными.

## Шаг 3. API

- Протокол **HTTP**: методы, статус-коды, заголовки.
- Проектирование **REST**: ресурсы, пагинация, фильтры, версии.
- **Валидация** входных данных и понятные ответы об ошибках.
- Документирование API, например в формате OpenAPI.

**Веха:** CRUD API для той же схемы: создание, чтение, обновление и удаление записей с валидацией и документацией.

## Шаг 4. Аутентификация и авторизация

- Разница между **аутентификацией** (кто вы) и **авторизацией** (что вам можно).
- Хеширование паролей, сессии и токены.
- Роли и права доступа.
- Базовые угрозы: SQL-инъекции, утечки секретов, отсутствие проверки прав.

**Веха:** регистрация и вход в ваш API, роли «пользователь» и «администратор», закрытые эндпоинты.

## Шаг 5. Тестирование

- **Unit-тесты** для бизнес-логики.
- **Интеграционные тесты** для API с тестовой базой данных.
- Запуск тестов автоматически при каждом push.

**Веха:** тесты покрывают основные сценарии API, а CI запускает их на каждый pull request.

## Шаг 6. Основы деплоя

- Базовые команды **Linux** и SSH.
- **Docker**: образ приложения и запуск вместе с базой данных.
- Переменные окружения и хранение секретов вне кода.
- Логи и простой мониторинг.

```yaml
services:
  api:
    build: .
    env_file: .env
    ports:
      - "8000:8000"
    depends_on:
      - db
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: example
```

**Веха:** проект запускается одной командой и доступен по публичному адресу.

## Типичные ошибки

| Ошибка | Как исправить |
|---|---|
| Учить несколько языков параллельно | Один язык до уровня уверенных проектов |
| Пропускать SQL, полагаясь на ORM | Писать запросы руками, смотреть, что генерирует ORM |
| Хранить пароли и ключи в коде | Переменные окружения, `.env` в `.gitignore` |
| Не писать тесты «пока учусь» | Начинать с тестов к ключевой логике |

## FAQ

### Какой язык выбрать для backend?

Тот, по которому больше вакансий в вашем регионе и который вам комфортен. Базы данных, HTTP, безопасность и деплой не зависят от языка, поэтому перейти на другой позже проще, чем кажется.

### Нужно ли знать frontend backend-разработчику?

Глубоко не обязательно, но базовое понимание HTML, JavaScript и того, как браузер вызывает API, помогает проектировать удобные интерфейсы взаимодействия и быстрее находить ошибки.

### Сколько проектов нужно для первой работы?

Важнее качество, чем количество. Один-два проекта, где есть база данных, API, авторизация, тесты и деплой, показывают больше, чем десяток учебных заготовок.
