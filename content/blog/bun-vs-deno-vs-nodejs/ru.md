## Короткий ответ

Все три рантайма запускают JavaScript вне браузера, но решают разные задачи:

- **Node.js** — стандарт индустрии. Самая большая экосистема, максимум документации и проверенных решений.
- **Bun** — ставка на скорость и «всё в одном»: пакетный менеджер, сборщик, тест-раннер и запуск TypeScript в одном бинарнике.
- **Deno** — ставка на безопасность и современные стандарты: доступ к сети и файлам выдаётся явно, TypeScript и форматтер встроены.

Если сомневаетесь — начинайте с Node.js. Переходить на другой рантайм стоит только ради конкретной выгоды, которую вы можете измерить.

## Сравнение по ключевым критериям

| Критерий | Node.js | Bun | Deno |
|---|---|---|---|
| Движок | V8 | JavaScriptCore | V8 |
| Совместимость с npm | Полная, это родная среда | Высокая, но бывают пробелы | Хорошая через `npm:` и `package.json` |
| TypeScript | Через инструменты или новые встроенные возможности | Запускает напрямую | Запускает напрямую |
| Встроенные инструменты | Тест-раннер, watch-режим | Менеджер пакетов, сборщик, тесты | Форматтер, линтер, тесты |
| Модель безопасности | Полный доступ по умолчанию | Полный доступ по умолчанию | Запрет по умолчанию, флаги разрешений |
| Зрелость в продакшене | Максимальная | Растёт | Растёт |

## Скорость

Bun часто показывает лучшие результаты в синтетических тестах: быстрый старт процесса, быстрая установка пакетов, быстрый HTTP-сервер. Но в реальном приложении узким местом обычно являются **база данных, сеть и внешние API**, а не рантайм.

Практическое правило: измеряйте свой сценарий. Если 90% времени запроса уходит на SQL, смена рантайма почти ничего не даст.

Где скорость Bun ощутима сразу:

- установка зависимостей в CI;
- запуск тестов и скриптов;
- холодный старт небольших сервисов.

## Совместимость с npm

Это главный практический вопрос. Node.js — эталон: любой пакет из npm рассчитан на него.

- **Bun** реализует большую часть API Node.js и читает `package.json`, поэтому многие проекты запускаются без изменений. Проблемы чаще всего возникают у пакетов с нативными модулями и у редких API.
- **Deno** поддерживает импорт `npm:`-пакетов и работу с `package.json`, но исторически строился вокруг URL-импортов и веб-стандартов, поэтому некоторые инструменты экосистемы Node требуют донастройки.

Перед переездом проверьте свои ключевые зависимости: ORM, драйвер базы, SDK платёжных систем, библиотеки для работы с изображениями.

## Безопасность

Deno по умолчанию запрещает доступ к сети, файлам и переменным окружения. Права выдаются явно:

```bash
deno run --allow-net --allow-read=./data server.ts
```

Это снижает риск, если зависимость окажется вредоносной. В Node.js и Bun скрипт по умолчанию получает все права процесса. В Node.js есть собственная модель разрешений, но её нужно включать отдельно.

## Как выбрать

- **Корпоративный бэкенд, долгая поддержка, большая команда** — Node.js.
- **Новый сервис, важны скорость разработки и CI, зависимости простые** — Bun стоит попробовать.
- **Скрипты, утилиты, edge-функции, важна изоляция** — Deno.
- **Только ускорить установку пакетов** — можно использовать Bun как менеджер пакетов, оставив Node.js рантаймом.

## Частые ошибки

- **Переезд ради бенчмарков.** Цифры из чужих тестов не равны выигрышу в вашем проекте.
- **Не проверили хостинг.** Не все платформы и Docker-образы одинаково поддерживают Bun и Deno.
- **Смешали рантаймы без договорённости.** Разработчик запускает Bun локально, а продакшен работает на Node — баги «у меня работает» гарантированы.

## FAQ

### Можно ли перевести существующий проект с Node.js на Bun?

Часто да, но не всегда без правок. Начните с запуска тестов под Bun в отдельной ветке и проверьте зависимости с нативными модулями.

### Deno совместим с Next.js и другими фреймворками?

Многие фреймворки работают через npm-совместимость, но официальная поддержка различается. Смотрите документацию конкретного фреймворка перед выбором.

### Нужно ли учить все три рантайма?

Нет. Достаточно уверенно знать Node.js — API и подходы во многом совпадают, и переключиться на Bun или Deno будет несложно.
