## Короткий ответ

Интеграция CRM — это правило: **любое обращение клиента автоматически превращается в запись в CRM** с контактом, источником и ответственным. Для этого подключаются три потока:

- **Сайт** — формы отправляют данные в CRM через API или вебхук.
- **Телефония** — виртуальная АТС передаёт события звонков и записи разговоров.
- **Мессенджеры** — чаты приходят через встроенные коннекторы CRM или через сервис-агрегатор.

Поверх них работают **дедупликация** и **отслеживание источников**, иначе база быстро превращается в набор повторов без понятного происхождения.

## Формы на сайте

Есть три способа передать заявку с сайта:

| Способ | Как работает | Когда выбирать |
|---|---|---|
| Встроенная форма CRM | Форма создаётся в CRM и вставляется на сайт кодом | Нужно быстро, дизайн формы не критичен |
| Вебхук или API | Ваша форма отправляет данные на сервер, сервер создаёт запись в CRM | Своя вёрстка, валидация, несколько CRM-сущностей сразу |
| Плагин CMS | Готовый модуль для движка сайта | Сайт на популярной CMS, есть поддерживаемый модуль |

При отправке через API важно, чтобы **серверная часть** обращалась к CRM: ключ доступа к CRM никогда не должен попадать в код, который загружается в браузер. Если CRM недоступна, заявку нужно сохранить и отправить повторно, а не потерять.

## Телефония

Виртуальная АТС подключается к CRM через готовое приложение или API. Типовая логика:

1. Входящий звонок → CRM ищет контакт по номеру.
2. Номер найден → менеджер видит карточку клиента во всплывающем окне.
3. Номер новый → создаётся лид или сделка с источником «Звонок».
4. Пропущенный звонок → задача перезвонить с крайним сроком.
5. После разговора → запись звонка и длительность прикрепляются к карточке.

Исходящие звонки тоже стоит делать из CRM: так вся история общения остаётся в одном месте.

## Мессенджеры и чаты

Telegram, WhatsApp, Instagram и онлайн-чат на сайте подключаются через коннекторы чатов в CRM или через сервис-агрегатор. Для WhatsApp обычно нужен официальный WhatsApp Business API через провайдера.

Проверьте, что диалог **привязывается к существующему контакту**, а не создаёт нового клиента при каждом сообщении, и что ответы менеджера из CRM доходят клиенту в тот же мессенджер.

## Дедупликация

Один и тот же человек может оставить форму, позвонить и написать в Telegram. Без правил дедупликации получится три карточки.

- **Нормализуйте телефоны** в единый формат с кодом страны: `+998901234567`, без пробелов, скобок и дефисов.
- Приводите **email к нижнему регистру** и убирайте пробелы.
- Ищите контакт **перед созданием** записи: сначала по телефону, затем по email, затем по идентификатору мессенджера.
- Если совпадение найдено — добавляйте новое обращение к существующему контакту, а не создавайте копию.
- Регулярно запускайте **поиск дублей** встроенным инструментом CRM для того, что всё-таки проскочило.

## Отслеживание источников

Чтобы понимать, какая реклама приводит клиентов, каждая заявка должна нести источник.

- **Формы**: сохраняйте UTM-метки при входе на сайт и передавайте их в скрытых полях.
- **Звонки**: используйте коллтрекинг — разные номера для разных каналов или подменные номера для каждого визита.
- **Чаты**: источник обычно определяется каналом (Telegram, Instagram), а для рекламы — по стартовому параметру или специальной ссылке.

Простой пример сохранения UTM-меток в скрытые поля формы:

```js
const params = new URLSearchParams(location.search);
for (const key of ["utm_source", "utm_medium", "utm_campaign"]) {
  const value = params.get(key);
  if (value) sessionStorage.setItem(key, value);
  const input = document.querySelector(`input[name="${key}"]`);
  if (input) input.value = sessionStorage.getItem(key) ?? "";
}
```

## Что проверить после настройки

- Отправьте тестовую заявку **через каждый канал** — форму, звонок, каждый мессенджер.
- Проверьте, что указан **источник** и UTM-метки.
- Повторите обращение с того же номера — новая карточка создаваться не должна.
- Убедитесь, что назначается **ответственный** и создаётся задача.
- Пропущенный звонок превращается в задачу перезвонить.
- Отключите CRM или передайте неверный ключ — заявка не должна пропасть бесследно.
- Через неделю сверьте количество заявок в CRM с данными телефонии и аналитики сайта.

## FAQ

### Нужен ли программист, если у CRM есть готовые интеграции?

Для типовых сценариев часто хватает готовых коннекторов. Разработка нужна, когда форма своя, нужна сложная дедупликация, несколько CRM-сущностей сразу или связка с системами, для которых готовой интеграции нет.

### Почему в CRM меньше заявок, чем в аналитике сайта?

Частые причины: ошибки отправки без повторной попытки, блокировка скриптов в браузере, формы, которые отправляют данные только на почту, или учёт в аналитике отправок, не прошедших валидацию. Сверьте логи сервера и CRM по конкретным датам.

### По какому полю лучше искать дубли?

Обычно по нормализованному телефону, затем по email. Имя для поиска дублей не подходит: оно слишком часто совпадает у разных людей и пишется по-разному у одного.
