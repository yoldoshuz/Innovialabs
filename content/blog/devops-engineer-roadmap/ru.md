## Последовательность навыков

DevOps-инженер помогает команде **быстро и надежно доставлять код до пользователей**: автоматизирует сборку, тесты, деплой и следит за стабильностью систем. Это роль, где все опирается на фундамент, поэтому порядок важен:

1. **Linux.**
2. **Сети.**
3. **Скрипты и Git.**
4. **Контейнеры**: Docker, затем основы оркестрации.
5. **CI/CD.**
6. **Облако и инфраструктура как код.**
7. **Мониторинг и логирование.**

Если начать с Kubernetes без Linux и сетей, любая проблема будет казаться необъяснимой.

## Шаг 1. Linux

- Файловая система, права доступа, пользователи и группы.
- Процессы, сервисы, `systemd`, просмотр логов.
- Пакетные менеджеры, SSH, ключи доступа.
- Базовые утилиты: `grep`, `find`, `tail`, `df`, `top`.

**Лабораторная:** поднимите виртуальную машину, настройте вход только по SSH-ключу, установите веб-сервер и разберитесь, где лежат его логи.

## Шаг 2. Сети

- Модель TCP/IP, IP-адреса, порты, подсети.
- **DNS**, **HTTP/HTTPS**, TLS-сертификаты.
- Балансировщики нагрузки и reverse proxy.
- Диагностика: `ping`, `curl`, `dig`, `ss`.

**Лабораторная:** настройте reverse proxy перед простым приложением, подключите домен и HTTPS-сертификат.

## Шаг 3. Скрипты и Git

- **Bash** для автоматизации рутинных задач.
- Один язык общего назначения на базовом уровне, часто это Python или Go.
- **Git**: ветки, слияние, pull request, работа в команде.

**Лабораторная:** скрипт, который делает резервную копию каталога, архивирует ее и удаляет старые копии.

## Шаг 4. Контейнеры

- Образ и контейнер, Dockerfile, слои, тома, сети.
- **Docker Compose** для локального окружения из нескольких сервисов.
- Основы **оркестрации**: зачем нужен Kubernetes, что такое pod, deployment, service.

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "app.py"]
```

**Лабораторная:** упакуйте приложение с базой данных в Compose, затем запустите его в локальном кластере Kubernetes.

## Шаг 5. CI/CD

- Конвейер: сборка → тесты → сборка образа → деплой.
- Хранение секретов в CI, а не в репозитории.
- Стратегии выката и откат при ошибке.

```yaml
name: ci
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker build -t app .
      - run: docker run --rm app python -m pytest
```

**Лабораторная:** при каждом push код тестируется, собирается образ, а изменения в основной ветке автоматически выкатываются на сервер.

## Шаг 6. Облако и инфраструктура как код

- Базовые сервисы любого облака: виртуальные машины, сети, хранилища, managed-базы, IAM.
- **Infrastructure as Code**: описывать инфраструктуру в файлах, например с Terraform.
- Управление конфигурацией, например с Ansible.

**Лабораторная:** опишите в коде сеть, виртуальную машину и правила доступа, создайте их одной командой и так же удалите.

## Шаг 7. Мониторинг и логирование

- Метрики, логи, трассировки.
- Алерты, которые сигнализируют о реальной проблеме, а не шумят.
- Дашборды по ключевым показателям сервиса.

**Лабораторная:** соберите метрики своего приложения, постройте дашборд и настройте оповещение о недоступности.

## Как не потеряться

| Ошибка | Что делать |
|---|---|
| Учить инструменты без понимания задачи | Сначала понять, какую проблему решает инструмент |
| Собирать сертификаты вместо практики | Каждый навык подтверждать лабораторной |
| Держать все в кликах в консоли облака | Описывать инфраструктуру в коде |
| Оставлять облачные ресурсы включенными | Удалять стенды после работы, следить за расходами |

## FAQ

### Можно ли стать DevOps-инженером без опыта разработки или администрирования?

Можно, но путь будет длиннее. Многие приходят в DevOps из системного администрирования или backend-разработки, потому что там уже есть фундамент из Linux, сетей и кода.

### Обязательно ли учить Kubernetes на старте?

Нет. Сначала уверенно освойте Linux, сети, Docker и CI/CD. Kubernetes логично изучать, когда понятно, какие проблемы контейнеров он решает.

### Какое облако выбрать для обучения?

Любое из крупных: базовые концепции у них схожи. Смотрите на вакансии в вашем регионе и обязательно ставьте лимиты расходов в учебном аккаунте.
