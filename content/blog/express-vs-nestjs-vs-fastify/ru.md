## Короткий ответ

- **Express** — если нужен небольшой API, прототип или вы хотите полный контроль над структурой.
- **Fastify** — если важны производительность, валидация по JSON Schema и аккуратная система плагинов.
- **NestJS** — если проект большой, команда растёт и нужна единая архитектура с модулями, DI и TypeScript.

Все три работают на Node.js и решают одну задачу — обработку HTTP-запросов. Отличаются они тем, сколько решений принимают за вас.

## Express: минимализм

Express — самый известный фреймворк Node.js. В нём есть роутинг, middleware и почти ничего больше.

```javascript
import express from "express";

const app = express();
app.use(express.json());

app.get("/health", (req, res) => {
  res.json({ status: "ok" });
});

app.listen(3000);
```

**Плюсы:** низкий порог входа, огромное количество примеров и middleware, полная свобода.

**Минусы:** структуру проекта, валидацию, обработку ошибок и типизацию придётся продумывать самостоятельно. В большой команде без договорённостей код быстро становится разнородным.

## Fastify: скорость и схемы

Fastify создавался с упором на производительность и низкие накладные расходы. Ключевая особенность — **схемы JSON Schema** для валидации входных данных и сериализации ответов.

```javascript
import Fastify from "fastify";

const app = Fastify({ logger: true });

app.get("/health", {
  schema: {
    response: { 200: { type: "object", properties: { status: { type: "string" } } } },
  },
}, async () => ({ status: "ok" }));

await app.listen({ port: 3000 });
```

**Плюсы:** высокая скорость, встроенный логгер, валидация из коробки, продуманная система плагинов с инкапсуляцией.

**Минусы:** экосистема меньше, чем у Express, а модель плагинов требует времени на освоение.

## NestJS: архитектура для команд

NestJS — фреймворк поверх Express или Fastify (адаптер выбирается). Он задаёт архитектуру: **модули, контроллеры, сервисы, внедрение зависимостей**, декораторы. TypeScript — основной язык.

```typescript
import { Controller, Get, Module } from "@nestjs/common";
import { NestFactory } from "@nestjs/core";

@Controller("health")
class HealthController {
  @Get()
  check() {
    return { status: "ok" };
  }
}

@Module({ controllers: [HealthController] })
class AppModule {}

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(3000);
}
bootstrap();
```

**Плюсы:** единая структура во всех модулях, удобное тестирование благодаря DI, готовые решения для валидации, авторизации, очередей, WebSocket, GraphQL и микросервисов.

**Минусы:** больше шаблонного кода, крутая кривая обучения для тех, кто не знаком с DI и декораторами, избыточен для маленьких сервисов.

## Сравнительная таблица

| Критерий | Express | Fastify | NestJS |
|---|---|---|---|
| Архитектура | Свободная | Плагины | Модули, DI |
| Производительность | Достаточная | Высокая | Зависит от адаптера |
| TypeScript | Через типы сообщества | Хорошая поддержка | Основной язык |
| Валидация | Сторонние библиотеки | JSON Schema встроена | Pipes и class-validator |
| Порог входа | Низкий | Средний | Выше среднего |
| Большие команды | Нужны свои правила | Нормально | Сильная сторона |

## Как выбрать

1. **Оцените размер и срок жизни проекта.** Небольшой сервис или бот — Express или Fastify. Продукт, который будут развивать годами, — NestJS.
2. **Посмотрите на команду.** Если есть опыт Angular или Spring, NestJS покажется знакомым. Если команда маленькая и хочет простоты — Express.
3. **Проверьте требования к нагрузке.** Если важна пропускная способность на каждом инстансе, обратите внимание на Fastify или NestJS с Fastify-адаптером.
4. **Не гонитесь за бенчмарками.** В реальных API время чаще уходит на базу данных и внешние сервисы, чем на сам фреймворк.

## Частые ошибки

- Брать NestJS для микросервиса из трёх эндпоинтов и тонуть в шаблонах.
- Писать большой проект на Express без договорённостей о структуре, валидации и ошибках.
- Смешивать middleware Express и плагины Fastify, не понимая различий.
- Выбирать фреймворк по популярности, а не по задачам проекта.

## FAQ

### Можно ли перейти с Express на NestJS позже?

Да, но это фактически переписывание слоя HTTP и структуры. Проще сразу выбрать NestJS, если вы ожидаете рост команды и функциональности.

### NestJS медленнее Express?

NestJS добавляет небольшой слой абстракций, но на практике разница редко заметна. Если важна скорость, NestJS можно запустить на адаптере Fastify.

### Какой фреймворк проще для начинающих?

Express: минимум концепций и много учебных материалов. После него проще понять, какие проблемы решают Fastify и NestJS.
