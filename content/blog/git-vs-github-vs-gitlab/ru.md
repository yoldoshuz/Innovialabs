## Короткий ответ

- **Git** — это **система контроля версий**: программа, которая запоминает каждое изменение в файлах, позволяет вести параллельные ветки и объединять их. Она работает локально и не требует интернета.
- **GitHub, GitLab, Bitbucket** — это **платформы**, которые хранят Git-репозитории на сервере и добавляют к ним всё, что нужно команде: pull/merge requests, код-ревью, задачи, CI/CD, права доступа.

Аналогия: Git — это формат и движок, как текстовый редактор, а GitHub — облачное хранилище с совместной работой поверх него. Git можно использовать без GitHub, а вот GitHub без Git — нет.

## Что делает Git сам по себе

- хранит историю коммитов и позволяет вернуться к любой версии;
- поддерживает **ветки** для фич и исправлений;
- объединяет изменения (`merge`, `rebase`) и показывает конфликты;
- синхронизируется с удалёнными репозиториями через `push` и `pull`.

```bash
git init
git add .
git commit -m "Первый коммит"
git remote add origin <адрес репозитория>
git push -u origin main
```

Последние две команды — это уже связь с платформой. Всё до них работает полностью офлайн.

## Что добавляют платформы

- **Pull request / merge request** — обсуждение и ревью изменений перед слиянием.
- **CI/CD** — автоматический запуск тестов и деплоя при каждом пуше.
- **Задачи и доски** — трекинг работы рядом с кодом.
- **Права доступа** — кто может читать, пушить, одобрять слияния.
- **Защита веток** — запрет прямых пушей в `main`, обязательное ревью.
- **Wiki, релизы, хранилище пакетов и контейнеров**.

## Сравнение GitHub, GitLab и Bitbucket

| | GitHub | GitLab | Bitbucket |
|---|---|---|---|
| Сильная сторона | Крупнейшее сообщество, open source | Полный DevOps-цикл в одном продукте | Интеграция с Jira и продуктами Atlassian |
| CI/CD | GitHub Actions | GitLab CI/CD | Bitbucket Pipelines |
| Ревью | Pull requests | Merge requests | Pull requests |
| Свой сервер | GitHub Enterprise Server (платно) | Self-managed, есть бесплатная Community Edition | Data Center (платно) |
| Кому подходит | Open source, большинство команд | Командам, которым нужен всё-в-одном и self-hosting | Командам, живущим в Jira |

Тарифы и лимиты бесплатных планов регулярно меняются, поэтому актуальные условия проверяйте на сайтах платформ перед выбором.

## Как выбрать платформу

1. **Где уже живёт команда?** Если задачи в Jira — Bitbucket даст удобные связи. Если важно сообщество и open source — GitHub.
2. **Нужен ли CI/CD из коробки?** Все три его дают, но конфигурации несовместимы: переезд потребует переписать пайплайны.
3. **Требования к данным.** Если код нельзя хранить в чужом облаке — смотрите на self-hosted варианты.
4. **Интеграции.** Проверьте, работают ли с платформой ваши мессенджеры, трекеры и сервисы деплоя.

Хорошая новость: репозиторий Git переносится между платформами без потери истории. Сложнее перенести задачи, ревью и пайплайны.

## Когда имеет смысл свой сервер

Self-hosting оправдан, если:

- **требования регулятора или заказчика** запрещают хранить код у внешнего провайдера;
- нужна работа **в закрытой сети** без доступа в интернет;
- нужен полный контроль над резервными копиями, обновлениями и доступом.

Минусы тоже реальны: за сервер, обновления безопасности, бэкапы и мониторинг отвечаете вы. Для небольшой команды без особых требований облачный вариант обычно проще и надёжнее. Помимо GitLab self-managed, есть лёгкие open source решения вроде **Gitea** и **Forgejo**, которые подходят для небольших установок.

## FAQ

### Можно ли пользоваться Git без GitHub?

Да. Git полностью работает локально. Удалённым репозиторием может быть любой сервер, сетевая папка или другая платформа.

### Сложно ли переехать с GitHub на GitLab или обратно?

Сам код с историей переносится простым `git push` в новый репозиторий, а у платформ есть инструменты импорта. Больше всего работы обычно занимает перенос CI/CD-конфигураций и интеграций.

### Что выбрать новичку?

Начните с изучения самого Git, а для хостинга возьмите любую популярную платформу — базовые навыки одинаково пригодятся на всех трёх.
