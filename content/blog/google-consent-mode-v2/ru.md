## Коротко: что такое Consent Mode v2

**Consent Mode** — это API в gtag.js и Google Tag Manager, который передаёт тегам Google Ads и GA4 состояние согласия пользователя. Сам по себе он ничего не спрашивает у посетителя: согласие собирает ваш cookie-баннер, а Consent Mode доносит результат до тегов.

Версия 2 добавила два сигнала к уже существующим. Итоговый набор для рекламы и аналитики:

| Сигнал | За что отвечает |
|---|---|
| `ad_storage` | cookie и хранилище для рекламы |
| `analytics_storage` | cookie для аналитики (GA4) |
| `ad_user_data` | можно ли отправлять в Google данные пользователя для рекламы |
| `ad_personalization` | можно ли использовать данные для персонализации и ремаркетинга |

У каждого сигнала два значения: `granted` или `denied`.

## Как это работает технически

Логика всегда одна: **сначала состояние по умолчанию, потом обновление**.

1. До загрузки тегов задаётся `default` — обычно всё `denied` для регионов, где нужно согласие.
2. Пользователь делает выбор в баннере.
3. Баннер вызывает `update` с новыми значениями.

```html
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('consent', 'default', {
    ad_storage: 'denied',
    analytics_storage: 'denied',
    ad_user_data: 'denied',
    ad_personalization: 'denied',
    wait_for_update: 500
  });
</script>
```

После клика «Принять» баннер вызывает `gtag('consent', 'update', {...})` с `granted` для разрешённых категорий. Параметр `wait_for_update` даёт баннеру время (в миллисекундах) загрузиться до первых хитов. Через параметр `region` можно задать разные значения по умолчанию для разных стран.

## Базовый и расширенный режим

| | Базовый (basic) | Расширенный (advanced) |
|---|---|---|
| Загрузка тегов до согласия | Теги заблокированы | Теги грузятся сразу |
| Данные без согласия | Не отправляются | Уходят **cookieless-пинги** без идентификаторов |
| Моделирование | Общая модель, менее точная | Модель на данных вашего сайта, точнее |
| Риск и сложность | Проще согласовать с юристами | Нужно убедиться, что пинги допустимы в вашей юрисдикции |

**Базовый режим** — консервативный выбор: пока нет согласия, Google не получает ничего. **Расширенный** отправляет обезличенные сигналы (факт события, без cookie), и это даёт Google больше материала для моделирования. Выбор режима — вопрос не только техники, но и позиции вашего юриста по конфиденциальности.

## Моделирование конверсий

Когда пользователь отказался от cookie, связать клик по рекламе с покупкой напрямую нельзя. Google восполняет пробел **моделированием**: по поведению согласившихся пользователей оценивает, сколько конверсий пришлось на отказавшихся.

Что важно знать:

- Смоделированные конверсии появляются в отчётах Google Ads вместе с наблюдаемыми и участвуют в автоматических стратегиях ставок.
- В GA4 есть отдельное **поведенческое моделирование**, но оно включается только при достаточном объёме трафика и ежедневных событий — на маленьком сайте его может не быть.
- Модель — это оценка, а не факт. Сверяйте динамику с данными CRM.

## Когда Consent Mode обязателен

С 2024 года Google требует передавать сигналы согласия, если вы используете рекламные функции (ремаркетинг, персонализацию, измерение конверсий) для пользователей из **Европейской экономической зоны**, а также Великобритании и Швейцарии. Без сигналов `ad_user_data` и `ad_personalization` аудитории и измерение для этого трафика деградируют.

Если ваша аудитория — только Узбекистан или СНГ, требование Google формально не применяется. Но если вы получаете хоть заметную долю трафика из ЕС или продвигаетесь туда, внедрять стоит сразу. Также проверьте требования местного законодательства о персональных данных — Consent Mode его не заменяет.

## Связка с баннером: пошагово

1. **Выберите CMP** (платформу управления согласием) с поддержкой Consent Mode v2. Для AdSense, Ad Manager и AdMob в ЕЭЗ Google требует сертифицированную CMP.
2. **Подключите через GTM**: у большинства CMP есть шаблон тега. Он ставится на триггер *Consent Initialization — All Pages*, чтобы `default` срабатывал раньше остальных тегов.
3. **Включите обзор согласий** в настройках контейнера GTM и проверьте, какие проверки согласия встроены в теги Google, а какие нужно добавить сторонним тегам вручную.
4. **Настройте регионы**: строгие значения по умолчанию для ЕЭЗ, более мягкие для остальных — если это допускает ваша политика.
5. **По желанию** включите `url_passthrough` (передача параметров кликов в URL без cookie) и `ads_data_redaction` (удаление рекламных идентификаторов при отказе).

## Как проверить внедрение

- В **Tag Assistant** откройте вкладку Consent: видно состояние по умолчанию и после обновления.
- В DevTools во вкладке Network у запросов Google есть параметры `gcs` и `gcd` — они кодируют состояние согласия.
- В Google Ads в диагностике конверсий отображается статус Consent Mode.

Частые ошибки:

- `default` срабатывает **после** первых тегов — первые хиты уходят без статуса.
- Баннер обновляет только `ad_storage` и `analytics_storage`, забывая про два новых сигнала.
- Теги Meta, TikTok и других систем продолжают работать без согласия: Consent Mode управляет только тегами Google.

## FAQ

### Можно ли внедрить Consent Mode без GTM?

Да. Достаточно вызвать `gtag('consent', 'default', ...)` в коде страницы до загрузки gtag.js и `update` из обработчика баннера. GTM просто упрощает управление и проверку.

### Consent Mode делает сайт соответствующим GDPR?

Нет. Он только передаёт выбор пользователя тегам Google. Соответствие закону зависит от баннера, политики конфиденциальности, списка обработчиков данных и того, как вы обращаетесь с данными.

### Почему после внедрения упало число конверсий?

Часть пользователей отказывается от cookie, и наблюдаемых конверсий становится меньше. Смоделированные конверсии появляются с задержкой и не во всех аккаунтах — при малом объёме данных модель может не включиться.
