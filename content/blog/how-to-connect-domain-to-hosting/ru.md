## Коротко: два способа

Привязать домен к хостингу — значит сказать DNS, куда отправлять посетителей. Есть два пути:

1. **Сменить NS-серверы.** Вы указываете у регистратора DNS-серверы хостинга, и всей DNS-зоной дальше управляет хостинг. Он сам создаёт нужные записи для сайта.
2. **Прописать записи вручную.** NS остаются прежними, а в текущей DNS-зоне вы добавляете **A-запись** с IP сервера (и **AAAA**, если есть IPv6) и **CNAME** для `www` или для облачной платформы.

| | Смена NS | Записи A/CNAME |
|---|---|---|
| Где живёт DNS | у хостинга | там же, где сейчас |
| Скорость применения | дольше, обычно до суток-двух | по TTL записи, часто минуты |
| Почта и другие записи | нужно воссоздать в новой зоне | остаются на месте |
| Когда подходит | всё у одного хостинга, домен новый | уже есть почта, сервисы, несколько серверов |

Если у домена уже работает корпоративная почта, безопаснее второй способ: вы меняете только записи сайта и ничего не теряете.

## Способ 1: смена NS-серверов

1. Добавьте домен в панель хостинга (раздел «Домены» или «Сайты»). Там же или в приветственном письме указаны NS-серверы, например `ns1.hosting.example` и `ns2.hosting.example`.
2. **Перед сменой** проверьте, есть ли у домена почта и другие записи. Если есть, создайте такие же MX, TXT (SPF, DKIM, DMARC) и прочие записи в зоне хостинга.
3. В панели регистратора найдите поле «DNS-серверы» или «Nameservers», замените старые значения на новые и сохраните.
4. Подождите обновления. Изменения NS проходят через зону верхнего уровня и кеши, поэтому обычно применяются в течение суток-двух.

## Способ 2: записи A и CNAME

1. Узнайте IP сервера в панели хостинга или облака. Для облачных платформ (Vercel, Netlify и подобных) возьмите значения из их инструкций — у каждого сервиса они свои.
2. Заранее, за день до изменений, уменьшите TTL текущих записей до 300 секунд — так переключение пройдёт быстрее.
3. В DNS-зоне домена создайте или измените записи:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | `203.0.113.10` |
| AAAA | `@` | IPv6 сервера, только если он есть |
| CNAME | `www` | `example.com.` |

4. Удалите старые A и AAAA для этих же имён — например, записи «парковки» регистратора.

**Важно:** CNAME нельзя ставить на сам домен (`@`), только на поддомены. Если платформа просит CNAME для корня, используйте **ALIAS/ANAME** или **CNAME flattening**, если их поддерживает ваш DNS-провайдер, либо A-запись, которую даёт платформа.

## Не забудьте про сервер

DNS только приводит посетителя к серверу. Сервер должен знать, какой сайт отдавать:

- на хостинге с панелью — добавить домен и `www` к сайту;
- на своём сервере — прописать имена в конфигурации веб-сервера, например в Nginx:

```nginx
server {
    listen 80;
    server_name example.com www.example.com;
    root /var/www/example;
}
```

После этого выпустите SSL-сертификат — без него браузеры покажут предупреждение.

## Как проверить результат

```bash
dig NS example.com +short
dig A example.com +short
dig CNAME www.example.com +short
dig @8.8.8.8 A example.com +short
curl -I http://example.com
```

В Windows вместо `dig` подойдёт `nslookup example.com 8.8.8.8`. Проверяйте через публичные резолверы и командную строку: браузер и провайдер могут показывать закешированный старый ответ.

## Частые ошибки

- **Сменили NS и потеряли почту** — MX и TXT не перенесли в новую зону.
- **Две A-записи** — старая и новая. Сайт открывается то с одного сервера, то с другого.
- **Забыли про `www`** — домен работает, `www` нет, или наоборот.
- **Старая AAAA-запись** — посетители с IPv6 попадают на прежний сервер.
- **Домен не добавлен на сервере** — DNS верный, но открывается заглушка хостинга.

## FAQ

### Сколько ждать, пока домен заработает?
Изменение A и CNAME обычно применяется в пределах TTL записи. Смена NS-серверов занимает дольше, как правило до суток-двух.

### Можно ли держать домен у одного провайдера, сайт у другого, а почту у третьего?
Да. Именно для этого подходит второй способ: DNS остаётся в одном месте, а записи указывают на разные сервисы — A на хостинг, MX на почтовый сервис.

### Что лучше для новичка?
Если домен новый и всё будет у одного хостинга, проще сменить NS. Если уже есть почта или другие сервисы, надёжнее менять только A и CNAME.
