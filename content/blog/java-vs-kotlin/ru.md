## Короткий ответ

**Kotlin** — современный язык от JetBrains, который работает на той же JVM, что и **Java**, и полностью с ней совместим. Google рекомендует Kotlin как основной язык для Android, и новые проекты там почти всегда пишут на нём. На бэкенде Java остаётся очень распространённой, а Kotlin — удобная альтернатива, которую можно внедрять постепенно.

## Null safety

В Java любая ссылка может оказаться `null`, и ошибка проявится только во время работы — `NullPointerException`. В Kotlin допустимость `null` — часть типа, и компилятор заставляет её обработать.

```java
// Java
String name = user.getName();
int len = name != null ? name.length() : 0;
```

```kotlin
// Kotlin
val name: String? = user.name
val len = name?.length ?: 0
```

Тип `String` в Kotlin не может быть `null`, а `String?` — может. Это убирает целый класс ошибок ещё до запуска.

## Многословность

Kotlin заметно короче. Классический пример — класс-модель данных.

```java
// Java (record, современный синтаксис)
public record User(String name, int age) {}
```

```kotlin
// Kotlin
data class User(val name: String, val age: Int)
```

Современная Java сократила разрыв: появились `record`, `var`, улучшенный `switch`. Но в Kotlin по-прежнему больше удобств: значения по умолчанию у параметров, именованные аргументы, функции-расширения, `when`, строковые шаблоны.

## Корутины и потоки

- **Java** исторически использует потоки ОС, `ExecutorService` и `CompletableFuture`. В новых версиях появились **виртуальные потоки**, которые делают блокирующий код дешёвым и масштабируемым.
- **Kotlin** предлагает **корутины**: асинхронный код пишется последовательно, через `suspend`-функции.

```kotlin
suspend fun loadProfile(id: Long): Profile {
    val user = api.getUser(id)        // приостановка без блокировки потока
    val orders = api.getOrders(id)
    return Profile(user, orders)
}
```

На Android корутины — стандарт для работы с сетью и базой без блокировки интерфейса.

## Совместимость

Kotlin и Java можно смешивать в одном проекте: вызывать Java-классы из Kotlin и наоборот. Это значит:

- можно переводить проект на Kotlin файл за файлом;
- доступны все Java-библиотеки: Spring, Hibernate, Jackson и другие;
- сборка через Gradle или Maven работает для обоих языков.

Есть нюансы: типы из Java приходят в Kotlin как «платформенные», и компилятор не знает, могут ли они быть `null`. Помогают аннотации `@Nullable`/`@NonNull` в Java-коде.

## Сравнение

| Критерий | Java | Kotlin |
|---|---|---|
| Null safety | Нет на уровне типов | Встроена в систему типов |
| Объём кода | Больше | Меньше |
| Асинхронность | Потоки, виртуальные потоки | Корутины |
| Android | Поддерживается | Рекомендуемый язык |
| Бэкенд | Огромная экосистема | Spring, Ktor, та же экосистема JVM |
| Скорость компиляции | Обычно быстрее | Обычно медленнее |
| Рынок разработчиков | Очень большой | Растущий |

## Как выбрать

- **Новое Android-приложение** — Kotlin, вместе с Jetpack Compose.
- **Существующий Android-проект на Java** — новые модули пишите на Kotlin, старый код переводите по мере изменений.
- **Новый бэкенд** — оба варианта хороши. Kotlin даёт лаконичность и корутины, Java — больше специалистов на рынке и предсказуемость.
- **Большая Java-кодовая база и команда Java-разработчиков** — переход ради моды не нужен; оцените выгоду и затраты на обучение.

## Частые ошибки

- Писать на Kotlin «как на Java» — без `data class`, null safety и функций-расширений.
- Злоупотреблять оператором `!!`, который отключает проверку на `null`.
- Смешивать корутины с блокирующими вызовами в главном потоке.

## FAQ

### Нужно ли знать Java, чтобы писать на Kotlin?

Нет, Kotlin можно изучать как первый язык. Но базовое понимание Java помогает читать документацию библиотек и разбираться в экосистеме JVM.

### Kotlin медленнее Java в работе?

Оба языка компилируются в байт-код JVM, поэтому производительность в работе обычно сопоставима. Разница чаще заметна во времени компиляции, а не в скорости выполнения.

### Можно ли использовать Kotlin вне Android и JVM?

Да, есть Kotlin Multiplatform для общего кода между Android, iOS и другими платформами, а также компиляция в JavaScript. Но основная зрелая экосистема по-прежнему связана с JVM и Android.
