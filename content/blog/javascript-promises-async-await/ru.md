## Коротко о главном

**Промис** — объект, который представляет результат асинхронной операции: он либо выполнится (fulfilled), либо отклонится с ошибкой (rejected). **async/await** — синтаксис поверх промисов, который позволяет писать асинхронный код так, будто он синхронный.

Три правила, которые закрывают большинство задач:

- ошибки ловите через `try/catch` вокруг `await`;
- независимые операции запускайте **параллельно** через `Promise.all`;
- не забывайте `await` — иначе получите промис вместо данных.

## От колбэков к промисам

Раньше асинхронность строилась на колбэках, и вложенность быстро росла:

```js
getUser(id, (err, user) => {
  if (err) return handle(err);
  getOrders(user.id, (err, orders) => {
    if (err) return handle(err);
    render(orders);
  });
});
```

С промисами это превращается в плоскую цепочку с одной точкой обработки ошибок:

```js
getUser(id)
  .then((user) => getOrders(user.id))
  .then((orders) => render(orders))
  .catch(handle);
```

## async/await: тот же код, только читаемее

```js
async function showOrders(id) {
  try {
    const user = await getUser(id);
    const orders = await getOrders(user.id);
    render(orders);
  } catch (err) {
    handle(err);
  } finally {
    hideLoader();
  }
}
```

Важно помнить: **async-функция всегда возвращает промис**. Даже `return 5` внутри неё вернёт `Promise<5>`.

Если ответ сервера с ошибкой (например, статус 404), `fetch` не отклоняет промис — проверяйте `response.ok` сами:

```js
const res = await fetch('/api/items');
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const items = await res.json();
```

## Параллельно или последовательно

Частая ошибка — ждать независимые запросы по очереди:

```js
// последовательно: второй запрос стартует только после первого
const user = await getUser(id);
const news = await getNews();
```

Если запросы не зависят друг от друга, запустите их одновременно:

```js
const [user, news] = await Promise.all([getUser(id), getNews()]);
```

Последовательность нужна, только когда следующий шаг использует результат предыдущего.

## Promise.all, allSettled, race, any

| Метод | Когда завершается | Когда использовать |
|---|---|---|
| `Promise.all` | все успешны или первая ошибка | все результаты обязательны |
| `Promise.allSettled` | когда все завершились | нужны и успехи, и ошибки |
| `Promise.race` | первый завершившийся, неважно как | таймауты |
| `Promise.any` | первый успешный | несколько зеркал одного ресурса |

Пример таймаута через `race`:

```js
const timeout = (ms) =>
  new Promise((_, reject) => setTimeout(() => reject(new Error('Timeout')), ms));

const data = await Promise.race([fetchData(), timeout(5000)]);
```

Для отмены самого `fetch` используйте `AbortController` — `race` лишь перестаёт ждать, но запрос продолжает выполняться.

## Частые ошибки

- **`await` внутри `forEach`.** `forEach` не ждёт промисы. Используйте `for...of` для последовательной обработки или `Promise.all` с `map` для параллельной.
- **Забытый `await`.** В переменной окажется промис, а ошибка уйдёт в необработанные.
- **Пустой `catch`.** Проглоченная ошибка — худший вид бага. Хотя бы логируйте её.
- **Слишком много параллельных запросов.** `Promise.all` по тысяче элементов может перегрузить API. Обрабатывайте пачками.
- **Смешивание стилей.** В одной функции лучше выбрать либо `then`, либо `await`.

```js
// неправильно
items.forEach(async (item) => await save(item));

// параллельно
await Promise.all(items.map((item) => save(item)));

// последовательно
for (const item of items) {
  await save(item);
}
```

## FAQ

### Что лучше: then или async/await?

Работают они одинаково, async/await просто читается легче, особенно с условиями и циклами. `then` удобен для коротких цепочек и там, где нельзя использовать `await`.

### Что будет, если один промис в Promise.all упадёт?

`Promise.all` сразу отклонится с этой ошибкой, результаты остальных вы не получите. Если нужны все результаты независимо от ошибок, используйте `Promise.allSettled`.

### Можно ли использовать await вне async-функции?

В ES-модулях есть top-level await — его можно писать на верхнем уровне модуля. В обычных функциях `await` работает только внутри `async`.
