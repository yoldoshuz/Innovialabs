## The short answer

Start with one question: **what should the visitor do?**

- Leave a request for one specific offer — you need a **landing page**.
- Understand who you are, what you do and why to trust you — a **corporate website**.
- Log in and get things done: order, calculate, manage data — a **web app**.

## Landing page

A **landing page** is a single page built around a single action: submit a request, book, buy.

Typical structure:

1. Hero section with the offer and a button.
2. The customer's problem and your solution.
3. Benefits, how it works, testimonials (if they are real).
4. Objection handling and FAQ.
5. Request form.

**Technologies:** anything from a site builder to a static site on Next.js or Astro. What matters is load speed, analytics and form integration with a CRM or Telegram.

**Timelines** are usually the shortest of the three. Missing copy, complex animation and long approvals stretch them.

## Corporate website

A **corporate website** has several sections about the company: services, case studies, team, blog, contacts. It works on trust and search.

Typical structure:

- home page with key directions;
- separate service pages (each can attract search traffic);
- portfolio or case studies;
- about, careers, contacts;
- blog or news.

**Technologies:** a CMS (WordPress or a headless CMS) plus a frontend. You need SEO setup, multilingual support if required, and a convenient admin.

**Timelines** depend on the number of pages, languages, content volume and whether you need a custom design.

## Web app

A **web app** is software in the browser: a client portal, a CRM, a booking service, an internal accounting system. The user does not read — they work.

What it usually includes:

- sign-up, login, roles and permissions;
- a database and server-side business logic;
- interfaces for different roles (client, manager, admin);
- integrations: payments (Payme, Click, Stripe), 1C, partner APIs;
- testing, monitoring, backups.

**Technologies:** a frontend in React, Next.js or Vue, a backend in Node.js, Python, Go or another language, a database, and deployment infrastructure.

**Timelines** are the longest and depend most on scope. That is why apps are usually launched as an **MVP** — a minimal version with the key scenarios — and developed in iterations.

## Comparison

| | Landing page | Corporate website | Web app |
|---|---|---|---|
| Goal | One target action | Trust and search | Solving user tasks |
| Size | One page | Many sections | Many screens and logic |
| Main metric | Conversion to request | Traffic and inquiries | Usage and retention |
| Backend | Minimal | CMS | Full |
| Maintenance | Occasional edits | Content updates | Continuous development |

## How to choose

- **Testing a new product or ad campaign** — start with a landing page.
- **Several services and search matters** — a corporate website.
- **Processes live in Excel and messengers and need automation** — a web app.
- **You need everything** — combine: a corporate site with separate campaign landing pages and a client portal as a separate app.

## Common mistakes

- **A landing page for ten services** — focus is lost and conversion drops.
- **A corporate site with no copy** — development stalls waiting for content.
- **A web app without priorities** — trying to build everything in version one delays launch.

## FAQ

### Can a landing page grow into a corporate website?

Yes. If the landing page is built on a solid stack, sections can be added. If it is made in a site builder, it is often simpler to build the site anew and reuse the blocks that worked.

### Do I need a corporate website if I have Instagram and Telegram?

Social networks are good for reach, but a website brings search traffic, control over content and a place all other channels can point to.

### How is a web app different from a mobile app?

A web app opens in a browser on any device without installation. A mobile app is installed from a store and gets deeper access to phone features. Many products start on the web.
