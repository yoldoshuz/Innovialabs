## Суть за минуту

База данных в Notion — это коллекция страниц, у каждой из которых есть одинаковый набор **свойств** (properties). Одни и те же записи можно показать в разных **представлениях** (views): таблица для учёта, доска для статусов, календарь для сроков. **Relations** связывают записи разных баз, например задачи с проектами, чтобы не копировать данные.

Работает правило: сначала продумайте свойства, потом стройте представления.

## Шаг 1. Создайте базу

1. На пустой странице наберите `/database` и выберите **Database – Full page** или **Database – Inline**.
2. Полностраничная база удобна как самостоятельный раздел («Задачи», «Клиенты»). Встроенная — когда таблица живёт внутри документа.
3. Дайте базе понятное имя во множественном числе: «Задачи», «Проекты», «Сотрудники».

Каждая строка базы — полноценная страница: внутри можно писать текст, вставлять чек-листы и файлы.

## Шаг 2. Выберите типы свойств

Тип свойства определяет, как по нему можно фильтровать и сортировать. Основные типы:

| Тип | Для чего | Пример |
|---|---|---|
| **Title** | Название записи, есть всегда | «Сверстать лендинг» |
| **Status** | Этапы работы с группами To-do / In progress / Complete | Бэклог, В работе, Готово |
| **Select** | Одно значение из списка | Приоритет: Высокий |
| **Multi-select** | Несколько тегов | Фронтенд, Дизайн |
| **Person** | Участник рабочего пространства | Исполнитель |
| **Date** | Дата или диапазон дат | Срок, Период спринта |
| **Number** | Числа с форматом: валюта, проценты | Бюджет |
| **Checkbox** | Да/нет | Оплачено |
| **Files & media** | Вложения | Договор в PDF |
| **URL / Email / Phone** | Контакты и ссылки | Сайт клиента |
| **Relation / Rollup / Formula** | Связи и вычисления | Проект, Прогресс |

Также есть системные свойства: **Created time**, **Created by**, **Last edited time** и **ID** для уникальных номеров.

Практические правила:

- Для этапов работы используйте **Status**, а не Select: он группирует значения и лучше работает с досками.
- Не храните исполнителя текстом — только **Person**, иначе не будет фильтра «Мои задачи».
- Если значений больше десятка и они постоянно добавляются, это, скорее всего, отдельная база и relation, а не Select.

## Шаг 3. Настройте представления

Нажмите **+** рядом с названием текущего представления и выберите тип. У каждого представления свои фильтры, сортировка, группировка и набор видимых свойств — данные при этом общие.

- **Table** — полный учёт, массовое редактирование.
- **Board** — доска Kanban, группировка по Status или Select. Карточка перетаскивается между колонками, и статус меняется сам.
- **Calendar** — записи по свойству Date. Подходит для сроков и контент-планов.
- **Timeline** — полосы по диапазону дат, удобно для роадмапа.
- **List** и **Gallery** — компактный список и карточки с обложками.

### Фильтры, которые стоит сделать сразу

- «Мои задачи»: `Исполнитель` → `contains` → `Me`. Каждый участник увидит своё.
- «Просрочено»: `Срок` → `is before` → `Today` и `Status` → `is not` → `Готово`.
- «На этой неделе»: `Срок` → `is within` → `This week`.

Фильтры можно объединять в группы **AND / OR** через Advanced filter. Называйте представления по смыслу: «Мои задачи», «Доска команды», «Сроки».

## Шаг 4. Свяжите базы через relations

Пример: базы «Проекты» и «Задачи».

1. В базе «Задачи» добавьте свойство **Relation** и выберите базу «Проекты».
2. Включите опцию показа связи в связанной базе, чтобы связь стала **двусторонней**: в каждом проекте появится список его задач.
3. Укажите лимит: одна задача — один проект, если так устроен процесс.

Теперь на основе relation можно добавить **Rollup** в «Проекты»: например, количество задач или процент выполненных.

### Связанные представления

На странице проекта вставьте `/linked view of database`, выберите «Задачи» и отфильтруйте по текущему проекту. Так внутри проекта появится его собственная доска задач.

## Частые ошибки

- **Одна база на всё**. Задачи, клиенты и заметки в одной таблице быстро становятся неуправляемыми.
- **Копии баз для каждой команды**. Лучше одна база и разные представления с фильтрами.
- **Слишком много свойств**. Показывайте в каждом представлении только нужные, остальные скройте.
- **Текст вместо типа**. Даты строкой и людей текстом не отфильтровать.

## FAQ

### Чем Status отличается от Select?

Status — специальный тип для этапов работы: значения сгруппированы в To-do, In progress и Complete, и на эти группы опираются доски, шаблоны и автоматизации. Select — просто одно значение из списка, например приоритет.

### Можно ли связать базы из разных teamspaces?

Да, relation работает между любыми базами одного рабочего пространства. Но участник увидит связанные записи только при наличии доступа к ним.

### Если я удалю представление, удалятся ли данные?

Нет. Представление — только способ показа. Данные пропадут, лишь если удалить сами записи или базу целиком.
