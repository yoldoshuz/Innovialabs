## Короткий ответ

Для управления проектами в Notion достаточно **трёх связанных баз данных**:

- **Проекты** — крупные цели с датами и владельцем.
- **Задачи** — конкретная работа с исполнителем, сроком и статусом.
- **Спринты** — короткие периоды, в которые команда берёт задачи.

Базы связываются через **relations**, а поверх них строятся представления: доска задач, таймлайн проектов и дашборд для каждого участника. Шаблон Notion Projects и встроенная настройка спринтов дают похожую схему из коробки — ниже логика, по которой её стоит собрать или проверить.

## База «Проекты»

| Свойство | Тип | Комментарий |
|---|---|---|
| Название | Title | «Редизайн сайта» |
| Статус | Status | Планирование, В работе, На паузе, Завершён |
| Владелец | Person | Один человек отвечает за результат |
| Сроки | Date (диапазон) | Начало и конец для таймлайна |
| Приоритет | Select | Высокий, Средний, Низкий |
| Задачи | Relation | Двусторонняя связь с «Задачами» |
| Прогресс | Rollup | Процент задач в группе Complete |

## База «Задачи»

| Свойство | Тип | Комментарий |
|---|---|---|
| Название | Title | Глагол + результат: «Сверстать форму заявки» |
| Статус | Status | Бэклог, К работе, В работе, На ревью, Готово |
| Исполнитель | Person | Один ответственный |
| Срок | Date | Дедлайн |
| Проект | Relation | Связь с «Проектами» |
| Спринт | Relation | Связь со «Спринтами» |
| Оценка | Number или Select | Часы или story points |
| ID | ID | Номер задачи для ссылок в чатах |

Правило: **один исполнитель** на задачу. Если работают двое, задачу стоит разделить.

## База «Спринты»

| Свойство | Тип | Комментарий |
|---|---|---|
| Название | Title | «Спринт 12» |
| Даты | Date (диапазон) | Обычно одна-две недели |
| Задачи | Relation | Связь с «Задачами» |
| Текущий | Formula | Отмечает активный спринт |
| Выполнено | Rollup | Процент выполненных задач |

Формула для свойства «Текущий»:

```js
dateStart(prop("Даты")) <= today() and dateEnd(prop("Даты")) >= today()
```

Тогда в «Задачах» формула ниже отметит задачи активного спринта, и по ней удобно фильтровать доску:

```js
prop("Спринт").filter(current.prop("Текущий")).length() > 0
```

## Представления, которые нужны каждый день

- **Доска спринта** — задачи, сгруппированные по статусу, фильтр «в текущем спринте».
- **Мои задачи** — фильтр `Исполнитель contains Me`, статус не «Готово», сортировка по сроку.
- **Бэклог** — задачи без спринта, сортировка по приоритету. Отсюда берут работу на планировании.
- **Таймлайн проектов** — база «Проекты» в представлении Timeline по свойству «Сроки». В таймлайне можно включить зависимости между записями.
- **Календарь сроков** — задачи по свойству «Срок».

## Дашборды

Дашборд — обычная страница со **связанными представлениями** (`/linked view of database`). Вариант для руководителя:

- проекты в работе с прогрессом;
- просроченные задачи по всем проектам;
- задачи на ревью;
- загрузка по исполнителям — таблица задач текущего спринта, сгруппированная по исполнителю.

Для участника: «Мои задачи», «Сегодня и просрочено», «Мои проекты». Если в вашем тарифе есть представление-диаграмма (chart), его удобно использовать для статусов и загрузки.

## Ритм работы

1. **Планирование**: из бэклога задачи переносятся в спринт через свойство «Спринт».
2. **Ежедневно**: каждый обновляет статусы на доске спринта.
3. **Ревью**: незавершённые задачи переносятся в следующий спринт или возвращаются в бэклог.
4. **Автоматизации** базы данных (на платных тарифах) берут рутину: например, проставляют дату при переходе в «Готово» или уведомляют исполнителя.

## Ограничения по сравнению с трекерами

Notion закрывает многие задачи, но у специализированных трекеров вроде Jira, Linear или YouTrack есть то, чего здесь нет или что делается обходными путями:

- **Жёсткий workflow**: в Notion нельзя запретить перевод задачи из «Бэклога» сразу в «Готово».
- **Отчёты Agile**: burndown, velocity и cycle time придётся собирать вручную или во внешних инструментах.
- **Связь с кодом**: ветки, коммиты и pull requests интегрированы слабее.
- **Масштаб**: на очень больших базах задач интерфейс замедляется.
- **Права на уровне задач** ограничены по сравнению с корпоративными трекерами.

Notion хорошо подходит небольшим командам, агентствам, маркетингу и операционным процессам. Если разработчиков много и процесс строгий, используйте трекер для задач, а Notion — для документации.

## FAQ

### Нужны ли спринты, если команда не работает по Scrum?

Нет. Базу «Спринты» можно не создавать и работать по Kanban: бэклог, доска со статусами и сроки. Спринты полезны, когда нужен регулярный ритм планирования.

### Как не утонуть в настройке?

Начните с базы «Задачи» и одной доски. Проекты и спринты добавляйте, когда задач станет много или появятся параллельные направления. Каждое новое свойство должно отвечать на конкретный вопрос.

### Можно ли подключить клиентов к проекту в Notion?

Да, через гостевой доступ к отдельной странице проекта. Лучше сделать для клиента отдельную страницу со связанным представлением, отфильтрованным по его проекту, а не открывать всю базу задач.
