## Короткий ответ

**Nuxt** — метафреймворк для Vue, **Next.js** — для React. Оба дают серверный рендеринг, статическую генерацию, файловый роутинг, API-эндпоинты и готовую сборку для продакшена. По возможностям они близки, поэтому главный вопрос не «какой лучше», а **на чём пишет ваша команда**:

- команда знает Vue или хочет более простой порог входа — **Nuxt**;
- команда знает React, нужен большой рынок разработчиков и библиотек — **Next.js**.

Менять библиотеку ради метафреймворка почти никогда не стоит. Ниже — различия, которые важны на практике.

## Режимы рендеринга

Оба фреймворка умеют одно и то же, но называют и настраивают это по-разному.

| Режим | Nuxt | Next.js |
|---|---|---|
| SSR (рендер на сервере) | по умолчанию | динамический рендеринг |
| SSG (статика при сборке) | prerender / `nuxi generate` | статический рендеринг, static export |
| SPA (только клиент) | `ssr: false` | клиентские компоненты, static export |
| Гибрид по маршрутам | `routeRules` | настройки сегмента, `revalidate` |
| Обновление статики | SWR/ISR через `routeRules` | ISR через `revalidate` |

**Главное отличие в архитектуре.** Next.js в App Router построен на **React Server Components**: компоненты по умолчанию выполняются на сервере и не отправляют свой JavaScript в браузер, а интерактивные части помечаются `"use client"`. Это уменьшает бандл, но требует понимать границу «сервер/клиент».

В Nuxt компоненты **универсальные**: рендерятся на сервере, затем гидрируются в браузере. Модель проще для понимания, а точечная оптимизация делается через серверные компоненты и ленивую загрузку.

## Роутинг

Оба используют **файловый роутинг**: структура папок превращается в адреса.

- **Nuxt**: файлы в `pages/`, например `pages/blog/[slug].vue`. Есть `layouts/` и middleware для маршрутов.
- **Next.js**: папки в `app/`, страница — это `page.tsx`, вложенные `layout.tsx` оборачивают дочерние маршруты. Есть `loading.tsx` и `error.tsx` для состояний.

Модель Next.js с вложенными лейаутами мощнее для сложных интерфейсов, но в ней больше специальных файлов и правил.

## Загрузка данных

**Nuxt** даёт композаблы `useFetch` и `useAsyncData`. Данные загружаются на сервере, передаются в браузер и не запрашиваются повторно при гидрации.

```vue
<script setup lang="ts">
const { data: posts } = await useFetch('/api/posts')
</script>
```

**Next.js** позволяет делать `async`-компоненты на сервере и обращаться к базе или API прямо в них. Для изменений данных есть **Server Actions** — серверные функции, которые вызываются из форм.

```tsx
export default async function Page() {
  const posts = await getPosts()
  return <PostList posts={posts} />
}
```

## Бэкенд внутри фреймворка

- **Nuxt** работает на серверном движке **Nitro**: API-маршруты лежат в `server/api/`, а сборка через пресеты адаптируется под Node.js, serverless, edge или статический хостинг.
- **Next.js** даёт **Route Handlers** в `app/` и Server Actions. Для простого бэкенда этого хватает, для сложной логики обычно выносят отдельный сервис.

## Экосистема и команда

| Критерий | Nuxt | Next.js |
|---|---|---|
| Библиотека | Vue | React |
| Порог входа | ниже, много автоимпортов | выше из-за RSC и кэширования |
| Модули | официальные модули Nuxt (изображения, контент, i18n) | огромная экосистема React |
| Рынок разработчиков | меньше | больше |
| UI-библиотеки | достаточно | максимальный выбор |

## Деплой

- **Next.js** проще всего разворачивать на Vercel, но он также запускается на своём сервере через Node.js или в Docker (режим `standalone`). Часть функций, например ISR и оптимизация изображений, на своём хостинге требует внимания к настройке.
- **Nuxt** благодаря Nitro собирается под множество платформ одной сменой пресета, включая обычный Node-сервер и статический хостинг.

## Типичные ошибки выбора

- **Выбирать по популярности**, а не по навыкам команды. Переобучение обходится дороже разницы в возможностях.
- **Брать метафреймворк без нужды.** Для внутренней админки без SEO может хватить обычного SPA на Vite.
- **Игнорировать хостинг.** Заранее проверьте, где будет работать проект и поддерживает ли платформа нужные режимы.
- **Не разобраться с кэшированием.** И в Nuxt, и в Next.js неверные настройки кэша приводят к устаревшим данным.

## FAQ

### Что лучше для SEO: Nuxt или Next.js?

Разницы нет. Оба отдают поисковикам готовый HTML через SSR или SSG и поддерживают мета-теги, sitemap и структурированные данные. На SEO влияет правильная настройка, а не выбор фреймворка.

### Можно ли перейти с Nuxt на Next.js или обратно?

Можно, но это фактически переписывание фронтенда: меняются библиотека компонентов, синтаксис и подход к данным. Переносятся только бизнес-логика, API и стили.

### Что выбрать, если команды ещё нет?

Посмотрите на рынок найма в вашем регионе и на требования проекта. Если важен большой выбор разработчиков и готовых библиотек, обычно выигрывает Next.js; если важны простота и скорость старта небольшой командой — Nuxt.
