## Главное различие

**Проприетарные модели** (через API OpenAI, Anthropic, Google и других) работают на серверах поставщика. Вы отправляете запрос и платите за объём. Весов модели у вас нет.

**Открытые модели** (open-weight: Llama, Qwen, Mistral и другие) можно скачать и запустить на своём сервере или в облаке. Вы управляете всем: где хранятся данные, какая версия работает, как модель дообучена.

Правильнее говорить «открытые веса», а не «open source»: у многих моделей открыты веса, но не данные обучения, а лицензия может содержать ограничения.

## Сравнение по ключевым критериям

| Критерий | Закрытые API | Открытые модели |
|---|---|---|
| Качество | Обычно на передовой, особенно в сложных рассуждениях | Хорошее, для многих задач достаточное; разрыв зависит от задачи |
| Старт | Минуты: ключ API и запрос | Нужны сервер с GPU, настройка, мониторинг |
| Стоимость | Оплата за токены, растёт с объёмом | Оплата за инфраструктуру и людей, мало зависит от числа запросов |
| Данные | Уходят поставщику по его условиям | Остаются в вашем контуре |
| Контроль версии | Поставщик может обновить или отключить модель | Версия меняется только по вашему решению |
| Дообучение | Ограниченные возможности | Полная свобода (fine-tuning, LoRA) |
| Лицензия | Условия использования сервиса | Разные лицензии, у некоторых есть ограничения |

## Когда выбирать закрытые API

- Нужен максимум качества: сложный анализ, код, многошаговые агенты.
- Вы проверяете гипотезу или делаете MVP и не хотите тратить время на инфраструктуру.
- Нагрузка небольшая или неравномерная.
- В команде нет специалистов по развёртыванию моделей.

## Когда выбирать открытые модели

- **Данные не должны покидать ваш контур**: требования регулятора, коммерческая тайна, персональные данные.
- **Большой стабильный объём** однотипных запросов, где оплата за токены становится заметной статьёй расходов.
- Нужна **работа без интернета** или в изолированной сети.
- Требуется **глубокое дообучение** под узкую задачу или язык.
- Важно, чтобы поведение модели не менялось без вашего ведома.

## Скрытые затраты открытых моделей

Модель бесплатна, но эксплуатация — нет. Заложите:

- **GPU-серверы**: свои или арендованные; большие модели требуют много видеопамяти.
- **Инференс-сервер** (например, vLLM или аналоги), балансировку и масштабирование.
- **Мониторинг**: задержки, ошибки, загрузка, качество ответов.
- **Обновления**: выход новых моделей, тестирование, миграция.
- **Безопасность**: доступ к эндпоинту, логи, фильтрация ввода.
- **Людей**, которые всё это поддерживают.

Небольшие модели можно запускать и на скромном железе, но их качество ниже — проверяйте на своих задачах.

## Лицензии: на что смотреть

- Разрешено ли **коммерческое использование**.
- Есть ли ограничения по **размеру компании** или числу пользователей.
- Можно ли использовать ответы модели для **обучения других моделей**.
- Требования к **указанию авторства** и распространению производных моделей.

Читайте лицензию конкретной версии модели — условия у разных семейств и даже версий различаются.

## Гибридный подход

Часто лучший вариант — комбинация:

- небольшая открытая модель на своём сервере для простых и массовых задач (классификация, извлечение данных, обработка внутренних документов);
- сильная закрытая модель через API для сложных запросов;
- маршрутизатор, который решает, куда отправить запрос.

Чтобы переключение было дешёвым, изолируйте вызов модели в отдельном слое кода с единым интерфейсом.

## Частые ошибки

- Разворачивать свою модель «на всякий случай», не посчитав полную стоимость владения.
- Сравнивать модели по общим рейтингам, а не на своих данных.
- Игнорировать лицензию до запуска в продакшен.
- Жёстко привязывать код к одному поставщику API.

## FAQ

### Открытая модель — это бесплатно?

Веса бесплатны, но за серверы, настройку и поддержку платить придётся. При малых объёмах API часто обходится дешевле.

### Можно ли отправлять персональные данные в закрытый API?

Зависит от законодательства, условий поставщика и вашего тарифа. Изучите политику обработки данных и требования к хранению персональных данных в вашей стране; при жёстких требованиях рассмотрите открытую модель в своём контуре.

### С чего начать?

С закрытого API и набора тестовых задач. Когда появится понятная причина — данные, объём, стоимость, — сравните на тех же задачах открытые модели.
