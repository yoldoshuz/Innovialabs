## Короткий ответ

Интеграция Payme устроена «наоборот»: не ваш сайт опрашивает Payme, а **Payme вызывает ваш endpoint** и спрашивает, можно ли принять платеж, создает транзакцию, проводит и при необходимости отменяет ее. Вам нужно:

1. Зарегистрироваться как мерчант и создать кассу.
2. Реализовать методы **Merchant API** на своем сервере.
3. Отправлять клиента на страницу оплаты Payme со ссылкой на заказ.
4. Пройти тесты в песочнице и переключиться на боевой ключ.

## Регистрация мерчанта

- Зарегистрируйте бизнес в кабинете Payme Business и заключите договор.
- Создайте **кассу** для сайта. Вы получите ID кассы (merchant ID), **тестовый ключ** и **боевой ключ**.
- Укажите в настройках кассы URL вашего endpoint и поле счета, по которому Payme будет искать заказ, например `order_id`.

Ключи храните в переменных окружения, не в репозитории.

## Как Payme вызывает ваш сервер

Каждый вызов — POST-запрос JSON-RPC 2.0 с заголовком `Authorization: Basic ...`, где закодировано `Paycom:<ключ кассы>`. Отвечать нужно всегда с HTTP 200, а ошибку передавать в теле ответа.

```ts
function isPaymeAuthorized(header: string | null, key: string): boolean {
  if (!header?.startsWith("Basic ")) return false;
  const decoded = Buffer.from(header.slice(6), "base64").toString();
  const sep = decoded.indexOf(":");
  return decoded.slice(0, sep) === "Paycom" && decoded.slice(sep + 1) === key;
}
```

При неверной авторизации возвращайте ошибку `-32504`.

## Методы Merchant API

| Метод | Что делает ваш сервер |
|---|---|
| `CheckPerformTransaction` | Проверяет, что заказ существует, не оплачен и сумма совпадает |
| `CreateTransaction` | Создает транзакцию в состоянии 1 или возвращает уже созданную с тем же `id` |
| `PerformTransaction` | Проводит транзакцию: состояние 2, заказ оплачен |
| `CancelTransaction` | Отменяет транзакцию: состояние -1 или -2 |
| `CheckTransaction` | Возвращает текущее состояние и время событий |
| `GetStatement` | Отдает список транзакций за период для сверки |

Суммы приходят **в тийинах**, время — в миллисекундах.

## Состояния транзакции

- **1** — создана, ожидает проведения.
- **2** — проведена, деньги списаны, заказ можно выполнять.
- **-1** — отменена до проведения.
- **-2** — отменена после проведения (возврат).

Храните в своей таблице: ID транзакции Payme, ID заказа, сумму, состояние, `create_time`, `perform_time`, `cancel_time` и причину отмены. Все ответы методов строятся из этих полей.

## Ключевые правила обработки

- **Идемпотентность.** Повторный `CreateTransaction` или `PerformTransaction` с тем же `id` должен вернуть тот же результат, а не создавать новую запись.
- **Один заказ — одна активная транзакция.** Если для заказа уже есть транзакция в состоянии 1, новую с другим `id` отклоняйте ошибкой из диапазона счета.
- **Таймаут.** Транзакция, которую не провели за отведенное в документации время, отменяется, а `PerformTransaction` по ней возвращает ошибку.
- **Отмена после проведения** разрешена, только если ваш бизнес-процесс допускает возврат. Если товар уже нельзя вернуть, отвечайте ошибкой невозможности отмены.
- **Фискальные данные.** Если касса требует фискализации, передавайте позиции чека с кодами ИКПУ в формате из документации.

## Ссылка на оплату

Клиента отправляют на страницу оплаты Payme. В ссылку кодируются ID кассы, поле счета и сумма в тийинах, а также, по желанию, URL возврата. Важно: возврат клиента на сайт **не подтверждает оплату**. Статус «оплачен» ставится только в `PerformTransaction`.

## Тестирование в песочнице

У Payme есть песочница, где вы указываете URL своего endpoint и тестовый ключ и прогоняете сценарии: неверная авторизация, несуществующий заказ, неверная сумма, создание, проведение, отмена до и после проведения, повторные вызовы. Боевой ключ подключайте только после того, как все сценарии проходят.

Подробная спецификация — в [документации Payme для разработчиков](https://developer.help.paycom.uz/).

## Типичные ошибки интеграции

- Сумма в сумах вместо тийинов: проверка суммы падает на каждом заказе.
- Ответ с HTTP 401 или 500 вместо HTTP 200 с объектом ошибки.
- Новая запись при повторном `CreateTransaction` вместо возврата существующей.
- Заказ помечается оплаченным на `CreateTransaction`, а не на `PerformTransaction`.
- Время в секундах вместо миллисекунд.
- Тестовый ключ в продакшене после запуска.

## FAQ

### Можно ли проверить статус платежа без callback от Payme?

В модели Merchant API источник правды — вызовы Payme к вашему серверу. Для сверки используйте свою таблицу транзакций и метод `GetStatement`, который Payme тоже вызывает у вас.

### Что делать, если Payme вызывает метод для уже отмененного заказа?

Отвечайте по состоянию, сохраненному в вашей базе: для `CheckTransaction` возвращайте текущее состояние, а для `PerformTransaction` по отмененной транзакции — ошибку о невозможности операции.

### Нужен ли отдельный endpoint для каждого метода?

Нет. Все методы приходят на один URL, а нужный обработчик выбирается по полю `method` в теле запроса.
