## Короткий ответ

Выбор BI-инструмента определяют две вещи: **где лежат данные** и **кто будет строить отчёты**.

- Данные в Google Sheets, GA4, Google Ads → **Looker Studio**.
- Данные в PostgreSQL или MySQL вашего продукта, нужен self-hosting → **Metabase**.
- Много источников, сложные расчёты, Excel и Microsoft 365 в компании → **Power BI**.

Дальше — подробности, которые помогут не ошибиться.

## Сравнение по ключевым критериям

| Критерий | Power BI | Metabase | Looker Studio |
|---|---|---|---|
| **Стоимость старта** | Desktop бесплатен, совместная работа — платные лицензии | Open-source версия бесплатна при self-hosting; есть платное облако и редакции | Бесплатно; платные — Pro-версия и часть коннекторов |
| **Источники** | Очень много: Excel, базы, облака, API | В основном SQL-базы и хранилища | Сервисы Google, BigQuery, несколько баз, партнёрские коннекторы |
| **Self-hosting** | Только через Power BI Report Server с особыми условиями лицензирования | Да, Docker или JAR-файл | Нет, только облако Google |
| **Порог входа** | Высокий: модель данных, Power Query, DAX | Низкий для бизнеса, SQL — для аналитиков | Самый низкий |
| **Моделирование** | Мощное: связи, меры, иерархии | Модели и метрики поверх SQL | Базовое: вычисляемые поля, blending |
| **Совместная работа** | Рабочие области, роли, приложения | Коллекции, группы, права на уровне данных | Доступ как в Google Docs |
| **Платформа автора** | Desktop только под Windows | Браузер | Браузер |

## Power BI: когда нужна глубина

**Сильные стороны:**

- Power Query для очистки данных из любых источников, включая «грязные» Excel-файлы.
- DAX и модель данных — сложные метрики, сравнение периодов, план-факт.
- Интеграция с Excel, Teams, SharePoint и учётными записями Microsoft.

**Ограничения:**

- Нужно учиться: без понимания модели «звезда» и контекста фильтров DAX быстро становится больно.
- Публикация и совместный доступ требуют лицензий или ёмкости — стоимость растёт с числом пользователей.
- Для обновления из локальных баз нужен gateway.

## Metabase: когда данные уже в SQL-базе

**Сильные стороны:**

- Ставится за минуты через Docker, работает внутри вашей инфраструктуры — данные не уходят наружу.
- Конструктор вопросов позволяет менеджерам строить отчёты без SQL, аналитики пишут нативный SQL.
- Простые дашборды, рассылки по расписанию, алерты, встраивание в продукт.

**Ограничения:**

- Нужен человек, который поддерживает сервер: обновления, бэкапы служебной базы, мониторинг.
- Плохо подходит для разрозненных Excel-файлов: данные лучше сначала загрузить в базу.
- Сложные модели и расчёты удобнее делать в SQL или в слое трансформаций до Metabase.

## Looker Studio: когда нужно быстро и бесплатно

**Сильные стороны:**

- Ноль установки, вход через Google-аккаунт, доступ как в Google Docs.
- Нативные коннекторы к GA4, Google Ads, Search Console, Sheets и BigQuery.
- Хорош для маркетинговых отчётов и клиентских дашбордов.

**Ограничения:**

- На больших Google Sheets и сложных blending-схемах становится медленным.
- Моделирование ограничено: сложную логику лучше готовить заранее в BigQuery или в базе.
- Коннекторы к сторонним системам часто платные и зависят от партнёров.

## Рекомендации по размеру компании

**Малый бизнес, 1–20 человек.** Данные в Sheets, CRM и рекламных кабинетах → Looker Studio. Если есть своя база и разработчик — Metabase.

**Стартап или продуктовая команда.** Данные в PostgreSQL или MySQL → Metabase на отдельном сервере, подключённый к **реплике** или read-only пользователю. Добавьте хранилище, когда отчёты начнут мешать продакшн-базе.

**Средняя и крупная компания.** Microsoft 365, 1С или ERP, финансовая отчётность → Power BI. Если нужна строгая изоляция данных внутри периметра, рассмотрите self-hosted Metabase или Power BI Report Server.

Частая и рабочая комбинация: Looker Studio для маркетинга и Metabase или Power BI для операционной и финансовой аналитики.

## Как выбрать за один день

1. Выпишите 3–5 отчётов, которые нужны прямо сейчас.
2. Отметьте источники каждого и кто будет их смотреть.
3. Соберите один и тот же отчёт в двух кандидатах — это быстрее любых обзоров.
4. Посчитайте стоимость с учётом числа зрителей и того, кто будет поддерживать систему.

## FAQ

### Можно ли начать с Looker Studio и потом перейти на Power BI?

Да. Отчёты не переносятся автоматически, но логика и требования к данным сохраняются. Чтобы переход был безболезненным, держите расчёты в базе или хранилище, а не только в формулах BI-инструмента.

### Безопасно ли подключать BI напрямую к продакшн-базе?

Только с осторожностью: тяжёлые запросы отчётов могут замедлить приложение. Используйте отдельного пользователя только на чтение и, по возможности, реплику или отдельное хранилище.

### Нужен ли SQL для работы с Metabase?

Для базовых отчётов нет — хватит визуального конструктора. Но SQL сильно расширяет возможности, поэтому хотя бы один человек в команде должен его знать.
