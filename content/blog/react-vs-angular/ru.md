## Короткий ответ

Главное различие — в философии. **React** — это библиотека для интерфейса: роутинг, формы, работу с данными и структуру проекта вы выбираете сами. **Angular** — полноценный фреймворк, где почти все уже решено: роутер, формы, HTTP-клиент, тестирование, CLI и единая архитектура.

- **React** подходит, когда нужна гибкость, быстрый старт, SEO через Next.js или мобильное приложение на React Native.
- **Angular** подходит для крупных корпоративных систем, больших команд и проектов на годы, где важны единые правила.

## Гибкость против «батареек в комплекте»

| Что нужно | React | Angular |
|---|---|---|
| Роутинг | сторонняя библиотека | встроенный `@angular/router` |
| Формы | React Hook Form, Formik и др. | встроенные Reactive Forms |
| HTTP | fetch, axios, TanStack Query | встроенный `HttpClient` |
| Состояние | Zustand, Redux Toolkit и др. | сервисы, signals, при необходимости NgRx |
| Структура проекта | на усмотрение команды | задана фреймворком и CLI |

Свобода React — плюс для опытной команды и минус для разрозненной: два React-проекта могут выглядеть совершенно по-разному. В Angular новый разработчик быстрее ориентируется в чужом коде, потому что структура типовая.

## TypeScript

В **Angular** TypeScript — стандарт: фреймворк написан на нем и рассчитан на него. Декораторы, строгая типизация шаблонов и сервисов работают сразу.

В **React** TypeScript опционален, но на практике используется в большинстве новых проектов. Типизация хорошая, но качество зависит от дисциплины команды и выбранных библиотек.

## Внедрение зависимостей (DI)

В Angular есть встроенный **механизм DI**: сервисы объявляются один раз и автоматически передаются в компоненты.

```ts
@Injectable({ providedIn: "root" })
export class UserService {
  private http = inject(HttpClient);
  getUsers() {
    return this.http.get<User[]>("/api/users");
  }
}
```

Это упрощает тестирование (сервис легко подменить заглушкой) и разделение логики по слоям. В React похожую роль играют **Context** и кастомные хуки — это проще, но правила организации кода придется договорить внутри команды.

## Инструменты

- **Angular CLI** генерирует компоненты, сервисы и модули, настраивает сборку, тесты и обновления версий.
- **React** обычно начинают через фреймворк (Next.js, React Router) или сборщик (Vite). Инструменты сильные, но выбор и настройка — на вас.

## Порог входа

React проще для старта: компонент — это функция, а основа — хуки. Angular требует освоить больше понятий сразу: компоненты, сервисы, DI, декораторы, RxJS, модули или standalone-компоненты. Зато после этого разработчик работает по единым правилам.

## Где что используют

- **Angular** часто выбирают банки, страховые компании, госсектор, внутренние корпоративные системы: сложные формы, много ролей, долгий жизненный цикл.
- **React** широко используют продуктовые компании, стартапы, интернет-магазины, медиа, а также команды, которым нужен общий подход для веба и мобильных приложений.

## Как выбрать

1. **Размер команды.** Чем больше людей и чем чаще они меняются, тем ценнее строгая структура Angular.
2. **Срок жизни проекта.** Системе на годы с единой архитектурой подойдет Angular; продукту, который быстро проверяет гипотезы, — React.
3. **SEO и публичные страницы.** Для них удобнее React с Next.js, хотя у Angular тоже есть рендеринг на сервере.
4. **Опыт команды.** Знакомый стек почти всегда выгоднее «правильного».
5. **Рынок найма.** React-разработчиков на рынке больше, Angular-специалисты чаще встречаются в корпоративном сегменте.

## Частые ошибки

- Брать Angular для небольшого лендинга — избыточно.
- Начинать большой React-проект без договоренностей об архитектуре — через год код трудно поддерживать.
- Считать, что Angular «устарел»: фреймворк активно развивается, появились signals и standalone-компоненты.

## FAQ

### Angular быстрее или медленнее React?

Для типичных бизнес-приложений разница несущественна. Скорость определяется архитектурой, объемом кода и работой с данными, а не самим выбором фреймворка.

### Можно ли использовать React для корпоративных систем?

Да, многие крупные системы построены на React. Нужно лишь заранее зафиксировать архитектуру, стек библиотек и правила кода, которые Angular дает по умолчанию.

### Нужно ли знать RxJS для Angular?

Базовое понимание желательно: HttpClient и ряд API построены на Observable. Но с появлением signals для простого состояния RxJS требуется реже.
