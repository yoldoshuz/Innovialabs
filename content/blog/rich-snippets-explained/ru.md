## Что такое расширенный сниппет

**Сниппет** — блок сайта в выдаче: заголовок, адрес и описание. **Расширенный сниппет** (rich snippet, rich result) показывает больше: рейтинг, цену, наличие, путь по разделам сайта, дату события.

Такой результат занимает больше места и сразу отвечает на часть вопроса пользователя. Сам по себе он не повышает позицию, но помогает выделиться среди соседних результатов.

Данные для расширенных сниппетов поисковик берёт из **структурированных данных** — специальной разметки на странице по словарю Schema.org.

## Основные типы

| Тип | Что видно в выдаче | Тип Schema.org |
|---|---|---|
| Рейтинг и отзывы | Звёзды и число оценок | `Review`, `AggregateRating` |
| Товар | Цена, наличие, рейтинг | `Product`, `Offer` |
| Хлебные крошки | Путь вместо длинного URL | `BreadcrumbList` |
| FAQ | Вопросы и ответы под сниппетом | `FAQPage` |
| Статья | Дата, автор, изображение | `Article` |
| Организация | Логотип, контакты | `Organization`, `LocalBusiness` |
| События | Дата и место | `Event` |
| Рецепты | Время, калорийность, фото | `Recipe` |

Учтите: Google постепенно сокращает набор типов, которые показывает. Например, FAQ-сниппеты сейчас выводятся только для ограниченного круга авторитетных сайтов. Перед внедрением сверяйтесь с актуальной документацией.

## Какую разметку использовать

Есть три формата: **JSON-LD**, **Microdata** и **RDFa**. Google рекомендует JSON-LD: он лежит отдельным блоком и не смешивается с вёрсткой. Яндекс тоже поддерживает Schema.org, в том числе JSON-LD.

Пример хлебных крошек:

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "Каталог", "item": "https://site.uz/catalog/" },
    { "@type": "ListItem", "position": 2, "name": "Ноутбуки", "item": "https://site.uz/catalog/laptops/" }
  ]
}
</script>
```

## Пошаговое внедрение

1. **Выберите типы**, которые соответствуют содержимому страницы: карточке товара — `Product`, статье — `Article`.
2. **Заполните обязательные и рекомендуемые поля** из документации поисковика.
3. **Генерируйте разметку из тех же данных**, что выводятся на странице — из CMS или базы, а не вручную.
4. **Проверьте** страницу в Rich Results Test от Google и в валидаторе микроразметки Яндекс Вебмастера.
5. **Следите за отчётами** об улучшениях в Search Console — там видны ошибки и предупреждения по всему сайту.

## Почему разметка есть, а сниппета нет

Корректная разметка делает страницу лишь **пригодной** для расширенного результата. Показ не гарантирован, потому что:

- поисковик решает, улучшит ли расширенный вид конкретную выдачу;
- для части типов есть ограничения по видам сайтов;
- разметка не совпадает с видимым содержимым страницы;
- страница ещё не переобойдена после изменений;
- у сайта в целом есть проблемы с качеством или нарушения правил.

## Частые ошибки

- **Разметка того, чего нет на странице.** Рейтинг или цена в JSON-LD должны быть видны пользователю.
- **Самостоятельные отзывы о себе.** Google не показывает звёзды для отзывов компании о самой себе в типах `Organization` и `LocalBusiness`.
- **Одинаковая разметка на всех страницах**, например FAQ из шаблона.
- **Устаревшие данные:** цена на странице изменилась, а в разметке осталась старая.

Манипуляции с разметкой могут привести к ручной мере, после которой расширенные результаты для сайта перестают показываться.

## FAQ

### Влияет ли микроразметка на позиции?

Напрямую — нет. Она помогает поисковику понять содержимое и может сделать сниппет заметнее, что влияет на кликабельность.

### Сколько ждать появления расширенного сниппета?

Точного срока нет. Сначала страница должна быть переобойдена, затем поисковик решает, показывать ли расширенный вид. Проверяйте статус в отчётах Search Console.

### Нужна ли отдельная разметка для Яндекса?

Обычно нет: Яндекс понимает Schema.org. Достаточно проверить страницы в его валидаторе и убедиться, что ошибок нет.
