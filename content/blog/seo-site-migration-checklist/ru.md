## Главное правило переезда

Поисковики уже знают ваши старые адреса и их ценность. Задача миграции — **передать эту ценность новым адресам** без разрывов. Для этого нужны три вещи: полная карта соответствия URL, корректные 301-редиректы и мониторинг после запуска.

Чем меньше вы меняете за один раз, тем проще найти причину просадки. Если можно, не совмещайте смену домена, CMS и структуры в одном релизе.

## Типы переездов и их риски

| Тип | Что меняется | Главный риск |
|---|---|---|
| HTTP → HTTPS | Протокол | Смешанный контент, забытые редиректы |
| Смена домена | Весь адрес | Потеря ссылочного веса без редиректов |
| Смена CMS | Шаблоны, URL, разметка | Пропавшие метатеги, новые адреса страниц |
| Смена структуры | Пути и вложенность | Тысячи 404, сломанная перелинковка |

## Чек-лист до запуска

1. **Соберите все старые URL**: краулер, sitemap, страницы с трафиком из аналитики, страницы с внешними ссылками из вебмастеров.
2. **Составьте карту URL**: старый адрес → новый адрес, один к одному. Не ведите всё на главную.
3. **Перенесите метаданные**: title, description, H1, canonical, hreflang, микроразметку.
4. **Сохраните контент**: тексты, изображения с alt, внутренние ссылки.
5. **Закройте тестовый стенд** от индексации паролем, а не только robots.txt.
6. **Зафиксируйте базу для сравнения**: трафик, позиции по ключевым запросам, число страниц в индексе.

## Редиректы: как сделать правильно

- Используйте **301** для постоянного переезда.
- Без цепочек: старый URL сразу ведёт на финальный.
- Для удалённых страниц без аналога — релевантный раздел или честный 404/410, а не главная.
- Протестируйте редиректы скриптом по всей карте до запуска.

Пример для nginx при смене домена:

```nginx
server {
    listen 443 ssl;
    server_name old-domain.uz www.old-domain.uz;
    return 301 https://new-domain.uz$request_uri;
}
```

## Чек-лист в день запуска

- Включите редиректы и снимите запрет индексации с нового сайта.
- Проверьте robots.txt, sitemap.xml с новыми URL, canonical на новые адреса.
- Добавьте новый сайт в Google Search Console и Яндекс Вебмастер.
- При смене домена используйте инструмент **смены адреса** в Search Console и настройку переезда в Яндекс Вебмастере.
- Обновите внутренние ссылки, чтобы они не шли через редиректы.

## Мониторинг после запуска

Первые недели проверяйте ежедневно:

- ошибки 404 и 5xx в логах и отчётах вебмастеров;
- число страниц в индексе по старому и новому сайту;
- трафик и позиции в сравнении с базой;
- Core Web Vitals новой версии.

Старые редиректы держите долго — не удаляйте их через месяц-другой.

## Критерии отката

Договоритесь заранее, при каких условиях откатываться:

- массовые 5xx или недоступность ключевых разделов;
- важные страницы выпадают из индекса и причину не удаётся быстро устранить;
- критичные ошибки в оплате или формах.

Небольшое временное колебание позиций после переезда — обычное явление. Откат нужен при технических поломках, а не при первой просадке.

## FAQ

### Сколько времени восстанавливается трафик после переезда?

Срок зависит от размера сайта и качества редиректов. Небольшие колебания нормальны, пока поисковики переобходят адреса. Если падение длится и растёт, ищите технические ошибки.

### Можно ли перенаправить все старые страницы на главную?

Нет. Поисковики воспринимают такие редиректы как мягкий 404, и вес страниц теряется. Ведите каждую страницу на ближайший по смыслу аналог.

### Нужно ли сохранять старый домен?

Да. Продлевайте его и держите редиректы, пока на старые адреса приходят люди и ссылки.
