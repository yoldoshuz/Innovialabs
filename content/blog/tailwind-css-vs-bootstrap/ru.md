## Главное различие

**Bootstrap** — компонентный фреймворк. Вы берёте готовые блоки: кнопки, карточки, модальные окна, навигацию, сетку — и собираете из них страницу. Внешний вид задан заранее, его можно настраивать через переменные Sass.

**Tailwind CSS** — utility-first фреймворк. Готовых компонентов в нём нет, есть набор мелких классов вроде `p-4`, `flex`, `text-lg`, `rounded-xl`. Вы собираете дизайн прямо в разметке.

Если коротко: **Bootstrap — это готовый конструктор с инструкцией, Tailwind — набор деталей под ваш собственный чертёж**.

## Один и тот же компонент в обоих

Карточка с заголовком, текстом и кнопкой.

Bootstrap:

```html
<div class="card" style="max-width: 20rem;">
  <div class="card-body">
    <h5 class="card-title">Тариф «Старт»</h5>
    <p class="card-text">Всё необходимое для запуска.</p>
    <a href="#" class="btn btn-primary">Выбрать</a>
  </div>
</div>
```

Tailwind CSS:

```html
<div class="max-w-xs rounded-xl border border-gray-200 p-6 shadow-sm">
  <h5 class="mb-2 text-lg font-semibold">Тариф «Старт»</h5>
  <p class="mb-4 text-gray-600">Всё необходимое для запуска.</p>
  <a href="#" class="inline-block rounded-lg bg-violet-600 px-4 py-2 text-white hover:bg-violet-700">
    Выбрать
  </a>
</div>
```

Что видно из примера:

- В Bootstrap разметка **короче**, а стиль уже готов — но он «бутстраповский».
- В Tailwind классов **больше**, зато каждый отступ, цвет и радиус под вашим контролем без отдельного CSS-файла.

## Сравнение по критериям

| Критерий | Bootstrap | Tailwind CSS |
|---|---|---|
| Подход | готовые компоненты | утилиты |
| Старт | очень быстрый | нужно собрать свои компоненты |
| Уникальный дизайн | требует переопределений | естественный путь |
| JS-компоненты | есть (модалки, дропдауны и др.) | нет, нужны отдельные библиотеки |
| Итоговый CSS | весь фреймворк, если не настроить сборку | только использованные классы |
| Разметка | компактная | многословная |
| Порог входа | низкий | средний: нужно знать CSS |

## Кастомизация

В Bootstrap цвета, шрифты и отступы меняются через переменные Sass. Это работает, пока дизайн близок к стандартному. Когда макет сильно отличается, появляются **слои переопределений**, которые трудно поддерживать.

В Tailwind дизайн-токены (цвета, шрифты, шкала отступов) описываются в конфигурации темы, и все утилиты строятся из них. Нестандартный макет — это обычная работа, а не борьба с фреймворком.

## Размер CSS

Bootstrap по умолчанию подключает стили всех компонентов. Его можно собрать из исходников только с нужными модулями, но это требует настройки.

Tailwind на этапе сборки сканирует файлы проекта и генерирует **только те классы, которые реально используются**. Поэтому итоговый CSS обычно небольшой, даже в крупном проекте.

## Порог входа

- **Bootstrap** понятен новичку: открыл документацию, скопировал компонент, получил результат.
- **Tailwind** требует понимать CSS: утилиты — это почти один к одному CSS-свойства. Зато знания переносятся, а не привязаны к фреймворку.

## Работа в команде

- В Bootstrap команда спорит о том, **как переопределить** компонент.
- В Tailwind важно договориться о **компонентах на уровне кода**: повторяющиеся наборы классов выносятся в React-, Vue- или серверные компоненты, а не копируются по проекту.
- Длинные строки классов помогает упорядочить официальный плагин для Prettier, который сортирует их автоматически.

## Как выбрать

Выбирайте **Bootstrap**, если:

- нужна админка или внутренний инструмент, где дизайн вторичен;
- нет дизайнера и макета;
- в команде мало фронтенд-опыта, а результат нужен быстро.

Выбирайте **Tailwind CSS**, если:

- есть уникальный макет или дизайн-система;
- проект на компонентном фреймворке (React, Vue, Svelte);
- важны размер CSS и единые токены по всему продукту.

Для Tailwind существуют наборы готовых компонентов, которые частично закрывают преимущество Bootstrap в скорости старта.

## FAQ

### Можно ли использовать Tailwind и Bootstrap в одном проекте?

Технически да, но это плохая идея: пересекающиеся имена классов, два подхода к стилям и лишний CSS. Если вы мигрируете, лучше переводить проект постепенно по страницам или компонентам.

### Tailwind не нарушает разделение HTML и CSS?

Он меняет границу: стили привязаны к компоненту, а не к отдельному файлу. В компонентных фреймворках это обычно упрощает поддержку, потому что всё, что относится к компоненту, находится в одном месте.

### Bootstrap устарел?

Нет, он активно развивается и остаётся хорошим выбором для интерфейсов, где важнее скорость сборки, чем уникальный внешний вид.
