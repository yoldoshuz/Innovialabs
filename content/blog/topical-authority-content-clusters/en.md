## What topical authority is

**Topical authority** is when a search engine treats your site as a reliable source on a whole topic rather than on a single query. A site that covers a topic thoroughly and consistently usually ranks better than a site with one strong article and scattered notes around it.

The main tool is the **pillar + cluster model**:

- **Pillar page** — a broad overview that answers the main question and leads to every subtopic.
- **Cluster pages** — in-depth pieces on each subtopic.
- **Internal links** tie them into one structure.

## Step 1. Map the topic

Start with audience questions, not a keyword list.

1. Define the **core topic** — what you want to be an expert in.
2. Collect queries: search suggestions, "People also ask", Wordstat, Search Console reports, questions from customers and sales.
3. **Group by intent**, not by words: if two queries return nearly the same results, they belong on one page.
4. Split groups into levels: main subtopics and narrow questions within them.

The result is a topic tree where each leaf is one page. Mark what already exists on your site and what needs to be created.

## Step 2. Design the pillar page

A good pillar page:

- fully answers the broad query (for example "inventory management") without diving deep into every detail;
- has a short section for each subtopic with a link to the detailed article;
- has clear navigation, such as a table of contents;
- is not just a list of links — it must be valuable on its own.

## Step 3. Design the cluster pages

Each cluster page:

- covers **one intent** completely;
- does not repeat neighbouring pages — otherwise they compete with each other (cannibalisation);
- links to the pillar and to 2–4 closely related cluster articles.

## Step 4. Link everything together

| Link | Purpose |
|---|---|
| Pillar → each cluster page | Shows search engines the topic structure |
| Cluster page → pillar | Passes weight to the main topic page |
| Cluster page → neighbours | Helps users go deeper |
| Breadcrumbs and sections | Reinforce hierarchy in URLs and navigation |

Use **descriptive anchors** ("how to choose a WMS") rather than "read more" or "here". Place links in the text where they genuinely help the reader.

## Step 5. Measure the result

Topical authority is not a single number, so look at the cluster as a whole:

- **Number of queries the cluster pages appear for** in Search Console — growth means search engines associate your site with the topic.
- **Share of topic queries in the top results**, not the position of individual keywords.
- **How quickly new cluster articles rank** — if new pieces enter the results faster, authority is growing.
- **Organic traffic and conversions** for the cluster's URL group.

Group cluster URLs by a shared path (for example `/blog/warehouse/`) or with filters, so you track the topic rather than individual pages.

## Common mistakes

- **Many thin articles** instead of fewer complete ones.
- **Cannibalisation** — several pages targeting one intent.
- **A pillar with no links to the cluster**, or a cluster with no links back.
- **Scattered focus**: a dozen topics covered lightly instead of depth in the main one.
- **Publish and forget** — outdated pieces weaken the entire cluster.

## FAQ

### How many articles should a cluster have?

There is no fixed number. Use the topic map: a cluster is complete when the audience's main questions are answered without duplicate pages.

### Can an existing article become the pillar page?

Yes, if it already ranks for the broad query. Expand it with overview sections and add links to the cluster pieces.

### Does this approach work for a small site?

Yes, even better: a small site gains more from covering one or two topics deeply than from writing shallowly about everything.
