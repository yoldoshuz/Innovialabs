## Короткий ответ

**Vite** — быстрый старт и мгновенные обновления в разработке почти без настройки. **Webpack** — зрелый и максимально гибкий сборщик с огромной экосистемой лоадеров и плагинов. Для новых проектов на React, Vue, Svelte или чистом TypeScript по умолчанию разумно выбирать Vite. Webpack оправдан там, где он уже глубоко встроен в проект или нужны его специфические возможности, например Module Federation в существующей архитектуре микрофронтендов.

## Что вообще делает сборщик

Браузеру нужен код, который он умеет выполнить, а разработчик пишет TypeScript, JSX, импортирует CSS, картинки и пакеты из `node_modules`. Сборщик:

- строит **граф зависимостей** от точки входа по всем `import`;
- **трансформирует** файлы: TS и JSX в JavaScript, современный CSS в совместимый;
- **объединяет и разбивает** код на чанки, удаляет неиспользуемое (tree shaking), минифицирует;
- добавляет **хэши в имена файлов** для долгого кэширования;
- в разработке поднимает **dev-сервер** с горячей заменой модулей (HMR).

## Чем они отличаются в разработке

**Webpack** перед запуском dev-сервера собирает бандл из всего приложения. Чем больше проект, тем дольше старт, а изменения пересобирают часть графа.

**Vite** использует нативные ES-модули браузера. Зависимости из `node_modules` один раз предварительно обрабатываются быстрым инструментом (esbuild), а исходный код отдается по запросу: браузер загружает только те модули, которые открывает страница. Поэтому старт почти не зависит от размера проекта, а HMR обновляет только измененный модуль.

## Сравнение по ключевым параметрам

| Параметр | Vite | Webpack |
|---|---|---|
| Старт dev-сервера | Быстрый, по требованию | Растет с размером проекта |
| HMR | Точечный, быстрый | Работает, но медленнее на больших графах |
| Конфигурация | Минимальная, разумные умолчания | Подробная, многое настраивается вручную |
| Плагины | Совместимы с API Rollup плюс свои хуки | Огромная экосистема лоадеров и плагинов |
| Production-сборка | Отдельный оптимизирующий бандлер | Тот же движок, что и в разработке |
| Legacy-браузеры | Через официальный плагин | Гибкая настройка через Babel и полифиллы |

Для production Vite все равно собирает бандл, потому что множество мелких модулей по сети работает хуже. Из-за того, что инструменты в dev и prod исторически различались, изредка встречаются расхождения поведения — их стоит проверять тестами на собранной версии.

## Конфигурация на практике

Минимальный конфиг Vite для React:

```ts
// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
});
```

Аналог в Webpack потребует описать entry, output, правила для TS/JSX, CSS и изображений, HTML-плагин и dev-сервер. Это не минус само по себе: такая явность дает полный контроль, но требует больше времени на поддержку.

## Когда миграция на Vite окупается

Переезд имеет смысл, если:

- старт dev-сервера и HMR заметно тормозят работу команды;
- конфиг Webpack разросся и его боятся трогать;
- проект использует стандартный стек без экзотических лоадеров.

Стоит подождать или отказаться, если:

- вы используете фреймворк со своим встроенным сборщиком (например, Next.js) — выбор делает фреймворк;
- в проекте много кастомных лоадеров без аналогов;
- приложение глубоко завязано на `require`, CommonJS и переменные окружения в стиле `process.env` — все это придется переписывать.

Порядок миграции: перенести `index.html` в корень, заменить переменные окружения на `import.meta.env`, подобрать плагины-аналоги, исправить импорты, затем прогнать тесты и сравнить production-сборку.

## Частые ошибки

- **Миграция ради моды** без измеренной проблемы.
- **Проверка только в dev-режиме.** Ошибки часто всплывают в production-бандле.
- **Перенос всего конфига сразу** вместо поэтапного запуска с минимальной настройкой.

## FAQ

### Vite подходит для больших проектов?

Да, подход «модули по требованию» как раз сильнее всего ощущается на больших кодовых базах. Ограничением обычно становятся не размеры, а специфические плагины и нестандартная настройка, которые придется переносить.

### Нужно ли учить Webpack, если все переходят на Vite?

Полезно понимать принципы: граф зависимостей, лоадеры, чанки, tree shaking. Они одинаковы для всех сборщиков, а Webpack еще долго будет встречаться в существующих проектах.

### Влияет ли выбор сборщика на скорость сайта для пользователей?

Напрямую почти нет: оба умеют минифицировать, разбивать код и кэшировать. Скорость для пользователя больше зависит от размера зависимостей, разделения кода и настройки кэширования.
