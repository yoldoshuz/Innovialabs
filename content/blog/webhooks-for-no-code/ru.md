## Вебхук простыми словами

**Вебхук (webhook)** — это HTTP-запрос, который сервис отправляет на ваш адрес, когда что-то произошло: пришла заявка, оплачен заказ, изменился статус сделки.

Сравните два подхода:

- **Опрос (polling)** — вы каждые несколько минут спрашиваете сервис: «Есть новые заявки?» Чаще всего ответ «нет», а реакция приходит с задержкой.
- **Вебхук** — сервис сам сообщает: «Вот новая заявка». Реакция почти мгновенная, лишних проверок нет.

| | Polling | Webhook |
|---|---|---|
| Кто инициирует | Ваша автоматизация | Сервис-источник |
| Скорость | С задержкой интервала | Почти сразу |
| Пустые запросы | Много | Нет |
| Что нужно | Доступ к API | Публичный URL для приёма |

## Как устроен payload

Вебхук обычно приходит как **POST-запрос** с телом в формате JSON. Это тело называют **payload**:

```json
{
  "event": "form.submitted",
  "created_at": "2026-05-12T09:30:00Z",
  "data": {
    "name": "Алишер",
    "phone": "+998901234567",
    "source": "landing"
  }
}
```

Кроме тела, важны **заголовки (headers)**: в них часто передают тип события, подпись или токен для проверки подлинности. Структуру payload конкретного сервиса ищите в его документации по вебхукам.

## Как принять вебхук в Zapier, Make и n8n

**Zapier**

1. Создайте Zap с триггером **Webhooks by Zapier** → *Catch Hook*.
2. Скопируйте выданный URL и вставьте его в настройки сервиса-источника.
3. Отправьте тестовое событие и нажмите *Test trigger* — Zapier покажет полученные поля.

Webhooks by Zapier доступен не на всех тарифах.

**Make**

1. Добавьте модуль **Webhooks** → *Custom webhook* и создайте новый вебхук.
2. Скопируйте адрес в сервис-источник.
3. Отправьте тестовое событие — Make автоматически определит структуру данных. Если поля потом изменятся, используйте *Redetermine data structure*.

**n8n**

1. Добавьте узел **Webhook**, выберите метод (обычно POST).
2. У узла два адреса: **Test URL** работает, пока вы нажали *Listen for test event*, а **Production URL** — когда workflow активирован.
3. Частая ошибка — оставить в сервисе-источнике тестовый адрес. После активации замените его на production.

## Как тестировать

- **Начните с реального события** из сервиса: тестовые данные «вручную» могут отличаться по структуре.
- Если сервис ещё не готов, отправьте запрос сами через Postman или `curl`:

```bash
curl -X POST "https://example.com/webhook/abc123" \
  -H "Content-Type: application/json" \
  -d '{"name":"Test","phone":"+998900000000"}'
```

- Проверьте **крайние случаи**: пустые поля, длинный текст, нелатинские символы.
- Посмотрите, как сервис ведёт себя при ошибке: многие отправляют вебхук **повторно**, если не получили успешный ответ. Значит, одно событие может прийти дважды — заложите проверку на дубли.

## Как защитить URL вебхука

URL вебхука — это фактически открытая дверь: кто знает адрес, тот может отправить туда данные.

- **Не публикуйте адрес** в коде фронтенда, скриншотах и открытых документах.
- **Проверяйте секрет.** Многие сервисы позволяют задать токен, который приходит в заголовке. В n8n у узла Webhook есть встроенная аутентификация (Header, Basic, JWT); в Zapier и Make проверку можно сделать фильтром по заголовку или полю.
- **Проверяйте подпись (HMAC)**, если сервис её отправляет: так вы убедитесь, что запрос пришёл именно от него и не был изменён.
- **Фильтруйте мусор:** отбрасывайте запросы без обязательных полей.
- **Смените адрес**, если он утёк, и обновите его в сервисе-источнике.

## FAQ

### Нужен ли сервер, чтобы принимать вебхуки?

Нет. Zapier, Make и облачный n8n дают готовый публичный адрес. Свой сервер нужен, только если вы разворачиваете n8n или собственный обработчик самостоятельно.

### Почему вебхук не срабатывает?

Чаще всего в сервисе-источнике указан неверный или тестовый адрес, сценарий не включён, либо сервис ждёт быстрый успешный ответ и считает доставку неудачной. Проверьте журнал доставки в сервисе-источнике — многие его ведут.

### Можно ли отправить вебхук из no-code инструмента?

Да. Все три платформы умеют отправлять HTTP-запросы: в Zapier это действие Webhooks by Zapier, в Make — модуль HTTP, в n8n — узел HTTP Request.
