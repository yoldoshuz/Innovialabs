## Короткий ответ

**Эмбеддинг** (embedding) — это способ превратить текст, картинку или товар в **вектор**: список из сотен или тысяч чисел. Модель подбирает эти числа так, чтобы **похожие по смыслу** объекты получали **похожие векторы**.

Компьютер не «понимает» слова так, как человек. Но он отлично умеет сравнивать числа. Эмбеддинги переводят смысл на язык, где сравнение становится простой математикой.

## Интуиция: карта смыслов

Представьте карту, где у каждой фразы есть координаты. На такой карте:

- «Как вернуть товар?» и «Хочу оформить возврат» стоят **рядом**, хотя общих слов почти нет.
- «Как вернуть товар?» и «Рецепт плова» — **далеко** друг от друга.

У обычной карты два измерения, у эмбеддингов — сотни. Но идея та же: **расстояние = различие в смысле**.

Отсюда главное преимущество перед поиском по ключевым словам: эмбеддинги находят **синонимы, перефразирования и даже текст на другом языке**, если модель многоязычная.

## Как измеряют похожесть

Чаще всего используют **косинусное сходство** (cosine similarity): насколько векторы смотрят в одном направлении. Значение ближе к 1 — смыслы близки.

```python
import numpy as np

def cosine(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
```

Сами векторы получают через API модели эмбеддингов или через открытую модель, запущенную на своем сервере.

## Где эмбеддинги применяют на практике

| Задача | Как работает |
|---|---|
| **Семантический поиск** | Запрос и документы превращаются в векторы, выдаются ближайшие |
| **RAG для чат-ботов** | Находят релевантные куски базы знаний и передают их LLM для ответа |
| **Рекомендации** | «Похожие товары» и «похожие статьи» по близости векторов |
| **Кластеризация** | Автоматически группируют отзывы, обращения или заявки по темам |
| **Дедупликация** | Находят почти одинаковые карточки товаров или дубли обращений |
| **Классификация** | Определяют категорию текста по близости к примерам |

## Как внедрить: шаги

1. **Выберите модель эмбеддингов.** Проверьте, поддерживает ли она ваши языки — для русского и узбекского это критично.
2. **Подготовьте данные.** Длинные документы режут на фрагменты (chunks) по смыслу: абзацы, разделы.
3. **Посчитайте векторы** для всех фрагментов и сохраните их вместе с исходным текстом.
4. **Храните и ищите.** Для небольших объемов хватит массива в памяти, для больших — векторная база или расширение для PostgreSQL.
5. **Проверьте качество** на реальных запросах пользователей.

## Частые ошибки

- **Смешивать векторы разных моделей.** Векторы от двух моделей несовместимы: при смене модели пересчитывайте все.
- **Слишком большие фрагменты.** Смысл «размывается», и поиск хуже находит конкретный ответ.
- **Слишком маленькие фрагменты.** Теряется контекст.
- **Отказ от ключевых слов.** Артикулы, коды и имена лучше искать обычным поиском. Часто лучший результат дает **гибридный поиск**: эмбеддинги плюс ключевые слова.
- **Нет оценки.** Без тестового набора запросов невозможно понять, стало ли лучше.

## FAQ

### Эмбеддинги и LLM — это одно и то же?

Нет. LLM генерирует текст, а модель эмбеддингов только превращает текст в вектор. Это отдельные модели, хотя их часто используют вместе, например в RAG.

### Нужна ли для эмбеддингов векторная база данных?

Не всегда. Для нескольких тысяч документов достаточно обычного хранения и перебора. Векторная база нужна, когда данных много и важна скорость поиска.

### Понимают ли эмбеддинги узбекский язык?

Зависит от модели. Многоязычные модели работают с узбекским, но качество стоит проверять на своих данных до запуска.
