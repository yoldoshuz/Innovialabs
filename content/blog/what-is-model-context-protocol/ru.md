## Коротко о MCP

**Model Context Protocol (MCP)** — открытый стандарт, который описывает, как ИИ-приложение подключается к внешним системам: базам данных, CRM, файлам, API. Его часто сравнивают с USB-C для ИИ: один разъём вместо множества разных переходников.

Без MCP каждое подключение ассистента к сервису делается отдельной интеграцией под конкретную модель и конкретное приложение. С MCP вы описываете доступ к системе **один раз**, и им может пользоваться любой ассистент, который поддерживает протокол.

## Какую проблему он решает

Языковая модель сама по себе знает только то, на чём её обучили. Чтобы она ответила, сколько заказов пришло сегодня, или создала задачу в трекере, ей нужен доступ к вашим системам.

До появления общего стандарта картина была такой:

- каждое ИИ-приложение придумывало свой формат подключения инструментов;
- одну и ту же интеграцию приходилось переписывать под разные ассистенты;
- смена модели или платформы означала переделку подключений.

MCP разделяет эти части: интеграция живёт отдельно и не зависит от того, какой ассистент к ней обращается.

## Как устроен MCP

В протоколе три роли:

| Роль | Что это | Пример |
|---|---|---|
| **Хост** | Приложение, с которым работает пользователь | Чат-ассистент, IDE, внутренний бот |
| **Клиент** | Компонент внутри хоста, держит соединение с одним сервером | Модуль подключения в ассистенте |
| **Сервер** | Программа, которая открывает доступ к данным или действиям | MCP-сервер для CRM, базы данных, файлов |

Сервер может предоставлять три вида возможностей:

- **Tools (инструменты)** — действия, которые модель может вызвать: создать сделку, отправить сообщение, выполнить поиск.
- **Resources (ресурсы)** — данные для контекста: документы, записи, файлы.
- **Prompts (шаблоны)** — готовые сценарии запросов, которые пользователь может выбрать.

Обмен сообщениями построен на **JSON-RPC**. Сервер может работать локально на компьютере пользователя или удалённо по HTTP. Подробная спецификация — на официальном сайте [modelcontextprotocol.io](https://modelcontextprotocol.io).

## Примеры интеграций для бизнеса

- **CRM.** Менеджер спрашивает ассистента: «Какие сделки зависли больше недели?» — ассистент получает данные через MCP-сервер CRM и отвечает.
- **База знаний.** Сотрудники ищут ответы во внутренних документах на обычном языке.
- **Аналитика.** Ассистент формирует запрос к базе данных и объясняет результат.
- **Таск-трекер и мессенджеры.** Создание задач, сводка по проекту, отправка уведомлений.
- **Собственные системы.** Учётная система или склад получают свой MCP-сервер, и ими можно пользоваться из любого совместимого ассистента.

## Безопасность: на что обратить внимание

MCP даёт модели доступ к реальным системам, поэтому вопросы безопасности здесь главные:

- **Минимальные права.** Сервер должен открывать только нужные операции. Чтение и запись лучше разделять.
- **Подтверждение действий.** Удаление, оплата, отправка писем — только после явного согласия пользователя.
- **Доверенные серверы.** Подключайте серверы из проверенных источников: сторонний сервер видит данные, которые через него проходят.
- **Инъекции через данные.** Текст из письма или документа может содержать инструкции для модели. Хост и сервер должны учитывать этот риск.
- **Логи.** Записывайте, какие инструменты и с какими параметрами вызывались.

## С чего начать

1. Выберите одну систему, к которой сотрудники чаще всего обращаются за данными.
2. Проверьте, нет ли для неё готового MCP-сервера.
3. Если нет — опишите 3–5 ключевых операций и реализуйте свой сервер с помощью официального SDK.
4. Начните с операций только на чтение, затем добавляйте действия с подтверждением.

## FAQ

### MCP работает только с одной моделью?

Нет. MCP — открытый протокол, и его поддерживают разные ИИ-приложения. Сервер, написанный по спецификации, не привязан к конкретной модели.

### Чем MCP отличается от обычного API?

API — это интерфейс конкретного сервиса. MCP — общий стандарт, по которому ИИ-приложение узнаёт, какие инструменты и данные доступны, и вызывает их. Часто MCP-сервер — это тонкая обёртка над существующим API.

### Нужно ли переписывать текущие системы под MCP?

Обычно нет. Достаточно написать MCP-сервер, который обращается к уже существующему API или базе данных и открывает ассистенту нужные операции.
