## Коротко: что такое Node.js

**Node.js** — это среда выполнения JavaScript вне браузера. Раньше JavaScript жил только на страницах сайтов, а Node.js позволил писать на нём серверы, скрипты и утилиты командной строки.

Важно: Node.js — это не язык и не фреймворк. Язык — JavaScript (или TypeScript), а Node.js даёт ему доступ к файлам, сети, процессам и операционной системе.

## Как он устроен

### Движок V8

Внутри Node.js работает **V8** — движок JavaScript из браузера Chrome. Он компилирует код в машинные инструкции на лету, поэтому JavaScript выполняется быстро.

### Неблокирующий ввод-вывод

Главная идея Node.js — **неблокирующий I/O** и **event loop** (цикл событий). Когда серверу нужно прочитать файл или сделать запрос к базе данных, он не ждёт ответа, а продолжает обрабатывать другие запросы. Когда данные готовы, вызывается обработчик.

```javascript
import { readFile } from "node:fs/promises";

const data = await readFile("config.json", "utf8");
console.log(JSON.parse(data));
```

Пока файл читается, процесс свободен для другой работы. Благодаря этому один процесс Node.js может обслуживать много одновременных соединений, если они в основном ждут сеть или диск.

### Экосистема npm

**npm** — менеджер пакетов и крупнейший реестр открытых библиотек для JavaScript. Почти для любой задачи — работа с датами, отправка писем, подключение к базе — есть готовый пакет. Это ускоряет разработку, но требует аккуратности с зависимостями.

## Для чего используют Node.js

- **API и бэкенд** для сайтов и мобильных приложений: REST, GraphQL, вебхуки.
- **Real-time приложения**: чаты, уведомления, совместное редактирование, онлайн-игры через WebSocket.
- **Боты и интеграции**: Telegram-боты, обмен данными между CRM, платёжными системами и сервисами.
- **Серверный рендеринг**: фреймворки вроде Next.js и Nuxt работают на Node.js.
- **Инструменты разработки**: сборщики, линтеры, тестовые раннеры, CLI-утилиты.
- **Микросервисы**: небольшие сервисы, которые быстро стартуют и легко упаковываются в Docker.

Отдельный плюс — **один язык на фронтенде и бэкенде**. Команда может переиспользовать типы, валидацию и часть логики.

## Где Node.js подходит плохо

| Задача | Почему сложно | Что обычно выбирают |
|---|---|---|
| Тяжёлые вычисления (видео, ML, сложная математика) | Долгая операция блокирует event loop, и остальные запросы ждут | Python, Go, Rust, C++ или вынос в отдельный сервис |
| Обучение моделей и анализ данных | Экосистема слабее, чем у Python | Python |
| Системное программирование | Нужен низкоуровневый контроль памяти | Rust, C, Go |

Для CPU-задач в Node.js есть **worker threads** и очереди задач, но это усложняет архитектуру. Если вычисления — суть продукта, честнее выбрать другой инструмент.

## Частые ошибки новичков

- **Синхронные операции в обработчиках запросов**: `readFileSync` в API блокирует весь сервер.
- **Неперехваченные ошибки в промисах**: процесс может упасть. Используйте `try/catch` с `await`.
- **Бездумные зависимости**: каждый пакет — это чужой код. Проверяйте популярность, поддержку и уязвимости (`npm audit`).
- **Нет process manager**: в продакшене нужен перезапуск при сбоях — через Docker, systemd или PM2.

## Как понять, подходит ли он вам

Node.js — хороший выбор, если:

1. Проект в основном работает с сетью, базой данных и внешними API.
2. Нужны real-time функции.
3. Команда уже знает JavaScript или TypeScript.

Стоит задуматься об альтернативах, если основная нагрузка — вычисления или работа с данными в стиле data science.

## FAQ

### Node.js — это фреймворк?

Нет. Это среда выполнения. Фреймворки вроде Express, NestJS или Fastify работают поверх Node.js и помогают структурировать серверный код.

### Можно ли писать на Node.js на TypeScript?

Да, это распространённая практика. TypeScript добавляет типы и помогает в больших проектах; код компилируется в JavaScript или запускается через инструменты, поддерживающие TypeScript.

### Выдержит ли Node.js большую нагрузку?

Для задач, связанных с вводом-выводом, — да, при правильной архитектуре: несколько процессов, балансировщик, кэш. Узким местом обычно становятся база данных и тяжёлые синхронные операции, а не сам Node.js.
