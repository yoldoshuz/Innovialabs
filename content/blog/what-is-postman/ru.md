## Что такое Postman

**Postman** — это клиент для работы с API. Он позволяет отправить запрос серверу и посмотреть, что тот ответил, без написания кода и без готового интерфейса сайта или приложения.

Кому он полезен:

- **Менеджерам** — проверить, что обещанная функция API действительно работает и что она возвращает.
- **QA-инженерам** — тестировать бэкенд отдельно от фронтенда и мобильного приложения.
- **Junior-разработчикам** — разобраться, как устроено чужое API, прежде чем писать интеграцию.

Postman есть как настольное приложение для Windows, macOS и Linux и как веб-версия. Для большинства функций нужен бесплатный аккаунт.

## Из чего состоит запрос

| Часть | Что это | Пример |
|---|---|---|
| **Метод** | Что вы хотите сделать | GET — получить, POST — создать |
| **URL** | Адрес ресурса | `https://api.example.com/users` |
| **Params** | Параметры в адресе после `?` | `?page=2&limit=20` |
| **Headers** | Служебная информация | `Content-Type: application/json` |
| **Body** | Данные, которые вы отправляете | JSON с полями нового пользователя |
| **Authorization** | Кто вы | токен или логин и пароль |

## Как отправить GET-запрос

1. Нажмите **New → HTTP** или «+» рядом со вкладками.
2. Оставьте метод **GET**.
3. Вставьте адрес, например `https://api.example.com/users`.
4. Если нужны параметры, добавьте их во вкладке **Params** — Postman сам допишет их к адресу.
5. Нажмите **Send**.

Внизу появится ответ сервера.

## Как отправить POST-запрос

POST обычно создаёт что-то новое: пользователя, заказ, заявку.

1. Выберите метод **POST** и укажите адрес.
2. Откройте вкладку **Body** и выберите формат.
3. Для JSON выберите **raw** и тип **JSON**, затем введите данные:

```json
{
  "name": "Aziza",
  "email": "aziza@example.com"
}
```

4. Нажмите **Send**.

Какие форматы тела бывают:

- **raw → JSON** — самый частый вариант для современных API.
- **form-data** — когда нужно отправить файл или поля формы.
- **x-www-form-urlencoded** — классические HTML-формы и некоторые старые API.
- **binary** — один файл целиком.

Какой формат нужен, написано в документации API. Если её нет — спросите разработчика.

## Заголовки

Заголовки сообщают серверу дополнительные сведения. Самые частые:

- **Content-Type** — в каком формате тело запроса. При выборе JSON во вкладке Body Postman подставит его сам.
- **Accept** — в каком формате вы хотите получить ответ.
- **Authorization** — данные для входа. Удобнее задавать через отдельную вкладку.

## Авторизация

Во вкладке **Authorization** выберите тип, который указан в документации API:

- **Bearer Token** — вставляете токен, Postman добавит заголовок `Authorization: Bearer <токен>`.
- **API Key** — ключ в заголовке или в параметрах адреса, название поля задаёт API.
- **Basic Auth** — логин и пароль.
- **OAuth 2.0** — Postman может сам пройти процедуру получения токена.

Не вставляйте боевые токены в запросы, которыми делитесь с коллегами, — для этого есть переменные и окружения.

## Как читать ответ

В блоке ответа смотрите на четыре вещи:

- **Код статуса** — главный признак успеха или ошибки.
- **Время** — сколько сервер отвечал.
- **Размер** ответа.
- **Body** — сами данные. Режим **Pretty** форматирует JSON для чтения.

Во вкладке **Headers** ответа видны служебные заголовки сервера, во вкладке **Cookies** — куки.

| Код | Значение |
|---|---|
| 200, 201 | Успех; 201 — ресурс создан |
| 400 | Ошибка в запросе: не те поля или формат |
| 401 | Не авторизованы: нет токена или он неверный |
| 403 | Авторизованы, но доступа нет |
| 404 | Ресурс не найден или неверный адрес |
| 500 и выше | Ошибка на стороне сервера |

## Полезные мелочи

- **Импорт cURL**: вставьте команду cURL через **Import** — Postman превратит её в готовый запрос.
- **Генерация кода**: значок `</>` справа покажет тот же запрос на JavaScript, Python, PHP и других языках.
- **Сохранение**: сохраняйте запросы в коллекции, чтобы не собирать их заново.

## FAQ

### Нужно ли уметь программировать, чтобы пользоваться Postman?

Нет. Для отправки запросов и чтения ответов достаточно понимать, из чего состоит запрос. Программирование пригодится позже, если вы захотите писать автоматические проверки.

### Чем Postman отличается от тестирования через браузер?

Браузер из адресной строки отправляет только GET-запросы без настройки заголовков и тела. Postman позволяет использовать любой метод, задавать заголовки, авторизацию и данные и подробно видеть ответ.

### Безопасно ли хранить токены в Postman?

Запросы и коллекции синхронизируются с облаком Postman. Секреты храните в переменных с типом secret и в текущих значениях окружения, а не в теле запроса или общем описании коллекции.
