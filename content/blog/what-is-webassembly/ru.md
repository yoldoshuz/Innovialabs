## Коротко о WebAssembly

**WebAssembly (Wasm)** — это бинарный формат кода, который браузер выполняет в той же песочнице, что и JavaScript, но ближе к скорости нативных программ. Пишут его обычно не вручную: код на C, C++, Rust или другом языке компилируется в файл `.wasm`, который загружается на страницу.

Wasm **не заменяет JavaScript**. Он работает рядом с ним: JavaScript управляет страницей, DOM и событиями, а Wasm берет на себя тяжелые вычисления.

## Как Wasm работает рядом с JavaScript

Схема взаимодействия:

1. Браузер загружает модуль `.wasm` и компилирует его.
2. JavaScript создает экземпляр модуля и получает доступ к его **экспортированным функциям**.
3. Модуль может вызывать функции, которые ему передал JavaScript (**импорты**).
4. Данные передаются через **линейную память** — общий буфер байтов, который видят обе стороны.

```js
const { instance } = await WebAssembly.instantiateStreaming(
  fetch("/math.wasm"),
  {}
);

console.log(instance.exports.add(2, 3)); // 5
```

Важный нюанс: Wasm **не имеет прямого доступа к DOM**. Любая работа со страницей идет через JavaScript. Поэтому частые вызовы между JS и Wasm с маленькими порциями данных могут свести выгоду на нет — лучше передавать работу крупными блоками.

## Какие языки компилируются в Wasm

| Язык | Инструменты | Особенности |
|---|---|---|
| **Rust** | wasm-pack, wasm-bindgen | Зрелая экосистема, удобная связка с JS, компактный результат |
| **C / C++** | Emscripten | Позволяет переносить существующие библиотеки и движки |
| **Go** | Встроенная поддержка, TinyGo | Стандартная сборка тянет рантайм, TinyGo дает файлы меньше |
| **AssemblyScript** | Собственный компилятор | Синтаксис похож на TypeScript, проще старт для JS-разработчиков |
| **C#, Kotlin и другие** | Blazor, Kotlin/Wasm | Переносят свой рантайм, файлы обычно крупнее |

Языки со сборщиком мусора исторически тащили его в бандл. Поддержка GC на уровне самого Wasm это меняет, но проверяйте состояние для конкретного языка и браузеров.

## Где Wasm действительно полезен

- **Обработка изображений и видео**: сжатие, конвертация форматов, фильтры прямо в браузере без отправки файла на сервер.
- **Редакторы и сложные приложения**: графические и CAD-редакторы, офисные инструменты, где важна скорость и уже есть большая кодовая база на C++ или Rust.
- **Игры и 3D**: движки, скомпилированные в Wasm, работают вместе с WebGL или WebGPU.
- **Перенос существующих библиотек**: базы данных, кодеки, парсеры, криптография — без переписывания на JavaScript.
- **Вычисления на клиенте**: симуляции, анализ данных, локальный запуск небольших ML-моделей.

## Когда Wasm не нужен

- Обычные сайты, лендинги, формы, интернет-магазины — узкое место там в сети, изображениях и рендеринге, а не в скорости вычислений.
- Логика, которая в основном **работает с DOM**: вызовы через JavaScript съедят выигрыш.
- Небольшие задачи, где современный JavaScript-движок и так достаточно быстр.

Прежде чем выбирать Wasm, **профилируйте**: убедитесь, что проблема именно в вычислениях.

## Ограничения

- **Размер файлов**: модуль с рантаймом языка может весить заметно больше эквивалентного JS.
- **Отладка** сложнее, хотя DevTools поддерживают source maps и DWARF для некоторых языков.
- **Нет прямого доступа** к DOM и большинству Web API — только через JavaScript-обертки.
- **Многопоточность** требует SharedArrayBuffer и специальных заголовков изоляции страницы.
- **Безопасность**: Wasm работает в песочнице, но уязвимости в исходном коде на C/C++ (например, переполнение буфера) могут повредить данные внутри памяти модуля.

## FAQ

### WebAssembly быстрее JavaScript?

Для интенсивных вычислений — часто да и, главное, предсказуемее по скорости. Для обычной логики интерфейса разница может быть незаметной, а накладные расходы на передачу данных — ощутимыми.

### Можно ли написать весь фронтенд на WebAssembly?

Можно, существуют фреймворки на Rust и C#. Но работа с DOM все равно идет через JavaScript, а размер загрузки обычно больше. Для большинства интерфейсов JavaScript и TypeScript остаются практичнее.

### Используется ли WebAssembly вне браузера?

Да. Благодаря WASI его запускают на сервере, на edge-платформах и в плагинных системах как безопасный изолированный формат исполняемого кода.
