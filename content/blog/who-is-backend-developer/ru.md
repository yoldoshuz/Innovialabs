## Коротко: кто это

**Backend-разработчик** отвечает за все, что происходит «за экраном». Пользователь нажимает «Оформить заказ» — интерфейс отправляет запрос на сервер, а дальше работает backend: проверяет данные, считает стоимость, сохраняет заказ в базе, списывает товар со склада и отправляет уведомление.

Если frontend — это витрина, то backend — это **склад, касса и бухгалтерия** вместе взятые.

## Реальные задачи backend-разработчика

### API

Backend отдает данные сайту, мобильному приложению или Telegram-боту через **API** — набор адресов, по которым клиент запрашивает или отправляет данные. Разработчик проектирует эти адреса, формат запросов и ответов, обработку ошибок.

```http
GET /api/orders/42
Authorization: Bearer <token>
```

### Базы данных

Нужно спроектировать, **как хранить данные**: какие таблицы, какие связи между ними, какие индексы ускорят поиск. А затем писать запросы так, чтобы система не замедлялась с ростом объема данных.

```sql
SELECT id, total, status
FROM orders
WHERE customer_id = 42
ORDER BY created_at DESC;
```

### Бизнес-логика

Правила, по которым работает бизнес: как считаются скидки, кто может отменить заказ, что происходит при возврате. Эти правила должны быть реализованы **точно и предсказуемо**, потому что ошибка здесь стоит денег.

### Интеграции

Подключение внешних сервисов: платежных систем, служб доставки, CRM, SMS-рассылок, мессенджеров. Backend-разработчик читает документацию чужого API, обрабатывает сбои и следит, чтобы данные не терялись.

### Надежность и безопасность

Авторизация и права доступа, защита от типовых уязвимостей, логирование, обработка ошибок, тесты. Backend должен работать стабильно, даже когда внешний сервис не отвечает.

## Навыки, которых ждут работодатели

- **Уверенное знание одного языка** и его основного фреймворка.
- **SQL и реляционные базы данных**: проектирование схем, запросы, индексы, транзакции.
- **HTTP и проектирование API**: методы, коды ответов, REST, аутентификация.
- **Git** и работа в команде через pull request.
- **Основы Linux и Docker**: запуск приложения, просмотр логов.
- **Тестирование**: умение писать автотесты для своего кода.
- **Понимание безопасности**: хранение паролей, валидация входных данных, права доступа.

Для junior-позиции обычно достаточно уверенной базы по первым четырем пунктам и знакомства с остальными.

## Популярные стеки

| Язык | Типичные фреймворки | Где часто встречается |
|---|---|---|
| **Python** | Django, FastAPI | Веб-сервисы, аналитика, AI-проекты |
| **JavaScript / TypeScript** | Node.js, NestJS, Express | Веб-приложения, когда команда пишет frontend и backend на одном языке |
| **PHP** | Laravel, Symfony | Сайты, интернет-магазины, CMS |
| **Java / Kotlin** | Spring | Крупные корпоративные системы, банки |
| **Go** | Стандартная библиотека, Gin | Высоконагруженные сервисы, инфраструктура |
| **C#** | ASP.NET | Корпоративные системы |

Какой язык выбрать, лучше решать по вакансиям в вашем регионе. Принципы backend-разработки — HTTP, базы данных, архитектура — одинаковы во всех стеках.

## Типичные ошибки новичков

- **Учить фреймворк без понимания SQL**: рано или поздно это приводит к медленным запросам.
- **Не обрабатывать ошибки** и надеяться, что внешний сервис всегда отвечает.
- **Хранить секреты в коде**: пароли и ключи должны лежать в переменных окружения.
- **Пропускать тесты**: в backend ошибки часто незаметны, пока не испортят данные.

## FAQ

### Нужна ли backend-разработчику сильная математика?

Для большинства задач достаточно логики и базовой математики. Углубленная математика нужна в отдельных областях — например, в машинном обучении или работе с большими данными.

### Сложнее ли backend, чем frontend?

Они сложны по-разному. Frontend требует внимания к интерфейсу и поведению в разных браузерах, backend — к данным, архитектуре и надежности. Выбирайте по тому, какие задачи вам интереснее.

### С какого проекта начать практику?

Сделайте простое API с базой данных: например, список задач или учет заказов с регистрацией пользователей. Добавьте проверку данных, обработку ошибок и тесты — это уже хороший проект для портфолио.
