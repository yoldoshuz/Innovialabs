## Коротко: кто это

**Frontend-разработчик** отвечает за ту часть сайта или веб-приложения, которую видит и с которой взаимодействует пользователь: страницы, кнопки, формы, анимации, личные кабинеты.

Его работа — взять макет от дизайнера и сделать из него **быстрый, удобный и корректно работающий интерфейс**, который одинаково хорошо выглядит на телефоне и на большом мониторе и получает данные с сервера.

## Чем он занимается каждый день

- **Верстка компонентов и страниц** по макетам из Figma.
- **Логика интерфейса**: формы с проверкой данных, фильтры, корзины, модальные окна.
- **Работа с API**: запросы к серверу, обработка ответов, состояния загрузки и ошибок.
- **Адаптивность**: интерфейс должен работать на любых размерах экрана.
- **Производительность**: оптимизация изображений, скорости загрузки, плавности.
- **Исправление ошибок** и код-ревью коллег.
- **Обсуждение задач** с дизайнером, backend-разработчиком и менеджером.

Значительная часть времени уходит не на написание нового кода, а на **чтение существующего**, отладку и согласование деталей.

## Базовый набор навыков

| Область | Что нужно знать |
|---|---|
| **HTML** | Семантическая разметка, формы, доступность |
| **CSS** | Flexbox, Grid, адаптивная верстка, анимации |
| **JavaScript** | Основы языка, работа с DOM, асинхронность, запросы к API |
| **TypeScript** | Типизация — во многих командах уже стандарт |
| **Фреймворк** | Один из популярных: React, Vue или Angular |
| **Инструменты** | Git, менеджеры пакетов, сборщики, DevTools браузера |

Пример того, с чем frontend-разработчик работает постоянно — запрос данных с сервера:

```javascript
async function loadProducts() {
  const response = await fetch("/api/products");
  if (!response.ok) throw new Error("Failed to load products");
  return response.json();
}
```

Кроме технических навыков важны **внимание к деталям**, умение задавать вопросы по макету и понимание того, как реальные люди пользуются интерфейсом.

## С кем он взаимодействует

- **Дизайнер** — уточнение поведения элементов, состояний, отступов, того, что не видно в статичном макете.
- **Backend-разработчик** — формат данных в API, обработка ошибок, авторизация.
- **QA-инженер** — воспроизведение и исправление найденных ошибок.
- **Менеджер проекта** — сроки, приоритеты, оценка задач.

Хороший frontend-разработчик — связующее звено: он одним из первых видит, что макет и API не стыкуются, и поднимает этот вопрос.

## Как роль отличается в разных компаниях

| Тип компании | Особенности работы |
|---|---|
| **Агентство / студия** | Много разных проектов и клиентов, сжатые сроки, разнообразие задач и технологий. Быстро растет кругозор. |
| **Продуктовая компания** | Один продукт на длительный срок, глубокая проработка качества, метрики, A/B-тесты, большая кодовая база. |
| **Стартап** | Высокая скорость, мало процессов, часто приходится брать задачи на стыке с backend и дизайном. |

Нет «лучшего» варианта: агентство дает широту опыта, продукт — глубину, стартап — самостоятельность.

## Типичные ошибки новичков

- **Сразу учить фреймворк**, пропуская основы JavaScript и CSS.
- **Игнорировать адаптивность** и проверять верстку только на своем экране.
- **Не обрабатывать состояния**: загрузку, пустые данные, ошибки сервера.
- **Забывать про доступность**: подписи полей, контраст, навигацию с клавиатуры.

## FAQ

### Нужно ли frontend-разработчику уметь рисовать или быть дизайнером?

Нет. Рисовать макеты — задача дизайнера. Но понимать основы композиции, типографики и отступов полезно: так легче реализовать макет точно и замечать нестыковки.

### Какой фреймворк учить первым?

Начните с того, который чаще всего встречается в вакансиях вашего региона. Важнее хорошо понимать JavaScript: с этой базой переход между фреймворками занимает немного времени.

### Чем frontend отличается от backend?

Frontend работает в браузере пользователя и отвечает за интерфейс. Backend работает на сервере и отвечает за данные, бизнес-логику и интеграции. Вместе они составляют полноценное веб-приложение.
