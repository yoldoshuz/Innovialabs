## The short answer

**UX (user experience)** is about how easy a product is to use: is the path to the goal clear, are there unnecessary steps, where do people get lost. **UI (user interface)** is the visual layer: grids, typography, color, components, button states.

A UI/UX designer covers both: they **understand the user's and the business's problem, design a solution and turn it into mockups** that developers can build. Large companies sometimes split the roles, but most job postings expect both.

## What the daily work looks like

- **Understanding the task**: what the business wants, who the users are, what scenarios they have.
- **Running or using research**: interviews, competitor analysis, analytics data, support feedback.
- **Designing structure**: user flows, screen maps, wireframes.
- **Prototyping** and testing ideas with users or within the team.
- **Producing final mockups** with every state covered: loading, error, empty screen, long text.
- **Maintaining the design system**: components, styles and rules for using them.
- **Supporting development**: answering questions, reviewing the implementation, adjusting designs.

## Working with developers and PMs

Designers rarely work alone. A typical set of relationships:

| With whom | What you align on |
|---|---|
| Product manager | goals, priorities, metrics, scope |
| Developers | feasibility, timelines, component behavior, responsiveness |
| QA | expected interface behavior, edge cases |
| Analysts | user behavior data, experiment results |

A good designer **talks to developers before the final mockups**, not after. That is the moment to learn that a solution would take disproportionate effort and to find a simpler option. Handoff files should answer questions in advance: spacing, states, behavior on small screens.

## What a junior designer needs to know

**Fundamentals:**

- composition, grids, typography, color and contrast;
- UX basics: usability heuristics, user flows, information architecture;
- common interface patterns for web and mobile platforms;
- accessibility basics: contrast, target sizes, clear labels.

**Tools:**

- **Figma**, the industry standard: auto layout, components, variants, prototyping;
- a basic understanding of HTML and CSS, not to write markup but to speak the same language as developers.

**Working habits:**

- explaining decisions through the user's problem rather than "it looks nicer";
- accepting critique and iteration calmly;
- asking questions until the task is clear.

## How to build a first portfolio

The most common beginner mistake is a portfolio of beautiful screens without context. Hiring managers want to see **how you think**.

1. Pick 2–3 problems: a redesign of a real service, a study project or a task for a business you know.
2. For each, describe **the problem, users, constraints, options considered, the result** and why you chose it.
3. Show intermediate steps: flows, wireframes, prototype.
4. Include the mobile version and interface states, not only the "perfect" screen.
5. Trim the text to what matters: a case study should be readable in a few minutes.

A concept redesign of a well-known app is fine, but label it honestly as a concept and explain which problem you were solving.

## FAQ

### Does a UI/UX designer need to be able to draw?

No, freehand drawing is not required. Understanding composition, typography and interface logic matters more. Illustration is a separate specialization.

### Does a designer need to know how to code?

Writing code is not required, but understanding HTML, CSS and platform constraints makes working with developers much easier and keeps designs realistic.

### Where do I start without experience?

Learn Figma and interface design fundamentals, then complete 2–3 projects with documented decisions. Feedback from practicing designers will speed up your progress more than yet another course.
