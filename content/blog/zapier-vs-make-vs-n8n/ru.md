## Короткий ответ

- **Zapier** — самый простой старт и самый широкий выбор готовых интеграций. Подходит для линейных автоматизаций «когда случилось X, сделай Y», которые собирают нетехнические команды.
- **Make** — визуальный холст, где сценарии ветвятся, проходят циклы и преобразуют данные. Подходит для сложной многошаговой логики.
- **n8n** — редактор из узлов, который можно запустить на своём сервере. Подходит, когда данные должны оставаться в вашей инфраструктуре, запусков много или разработчики хотят добавлять код.

Все три соединяют приложения через триггеры и действия и умеют обращаться к любому API через HTTP-запросы и вебхуки, если готовой интеграции нет.

## Модели оплаты

Важнее не цена на главной странице, а то, что именно платформа считает.

| Платформа | Что считается | Что это значит |
|---|---|---|
| Zapier | **задачи (tasks)**: успешно выполненные шаги-действия | Zap из пяти шагов тратит несколько задач за запуск |
| Make | **операции**: каждое выполнение модуля, включая проверку триггера | много шагов или длинные циклы быстро накапливаются |
| n8n Cloud | **выполнения (executions)**: один полный запуск процесса | число шагов не влияет на счёт |
| n8n на своём сервере | сервер и поддержка | платы за запуск нет, платите инфраструктурой и временем |

Чтобы сравнить честно, возьмите один реальный сценарий, оцените, сколько раз в месяц он запускается и сколько в нём шагов, и посчитайте стоимость по актуальным страницам тарифов каждой платформы. Проверьте также, какие функции (премиум-приложения, частая проверка триггеров, командный доступ) есть только на старших тарифах.

## Интеграции

- У **Zapier** самый большой каталог готовых коннекторов, включая много нишевых SaaS.
- У **Make** тоже большой каталог, а его модули часто открывают больше операций API для одного приложения.
- У **n8n** меньше встроенных узлов, зато есть мощный узел **HTTP Request**, узлы сообщества и возможность написать свой.

Перед выбором проверьте, что есть именно нужные вам триггеры и действия, а не только название приложения. «Поддерживает CRM X» может означать две операции из двадцати нужных.

## Визуальная логика

- **Zapier** строит Zap как последовательность шагов. Ветвление делается через Paths и фильтры. Это легко читать, но со сложной логикой становится тесно.
- **Make** показывает сценарий схемой: **роутеры** для веток, **итераторы** и **агрегаторы** для массивов, фильтры на любой связи. Виден весь поток данных и то, что получил каждый модуль.
- **n8n** — тоже холст из узлов: IF и Switch для ветвления, Merge для объединения потоков и узел **Code** для JavaScript или Python. Самый гибкий вариант для разработчиков, требует чуть больше технического понимания.

## Обработка ошибок

Ошибки неизбежны: API недоступен, поле пустое, превышен лимит. Важно, как вы их заметите и восстановитесь.

- **Zapier**: история запусков, письма об ошибках, автоматический повтор упавших шагов и ветки обработки ошибок на отдельных тарифах.
- **Make**: **обработчики ошибок**, привязанные к модулю, с директивами Resume, Ignore, Break, Rollback; незавершённые выполнения можно сохранять и перезапускать.
- **n8n**: **Retry On Fail** для каждого узла, возможность продолжить при ошибке и увести сбой в отдельный выход, а также **Error Workflow**, который запускается при падении процесса, например чтобы отправить уведомление в мессенджер.

Что бы вы ни выбрали, с первого дня настройте уведомления о сбоях и делайте шаги безопасными для повтора, чтобы перезапуск не создавал дубли записей.

## Self-hosting и контроль данных

Zapier и Make работают только в облаке: данные проходят через их серверы. Для многих команд это нормально, но проверьте, где обрабатываются данные, если вы работаете с персональной или финансовой информацией.

n8n можно установить на свой сервер, и данные останутся внутри вашей инфраструктуры. Минимальный локальный запуск из официальной документации:

```bash
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n
```

Для продакшена понадобятся ещё домен с HTTPS, база данных, бэкапы, обновления и мониторинг. Изучите условия лицензии n8n, если планируете использовать его в коммерческом продукте.

## Как выбрать под сценарий

| Сценарий | Что подойдёт лучше |
|---|---|
| Маркетинг или продажи связывают популярные SaaS без разработчиков | Zapier |
| Многошаговая логика с ветками, массивами и преобразованием данных | Make |
| Много запусков в месяц, оплата за шаг становится дорогой | Make или n8n |
| Данные должны оставаться на ваших серверах, требования регуляторов | n8n на своём сервере |
| В команде есть разработчики, нужен свой код и внутренние API | n8n |
| Критичный процесс с высокой нагрузкой и строгими требованиями к надёжности | собственный сервис интеграций |

## FAQ

### Можно ли перенести автоматизации с одной платформы на другую?

Автоматического конвертера нет. Процессы пересобираются вручную, поэтому держите простое описание каждой автоматизации: триггер, шаги, поля и обработка ошибок. Это сильно ускоряет переезд.

### n8n на своём сервере бесплатный?

Программой можно пользоваться без лицензионной платы в рамках условий лицензии, но хостинг не бесплатен: вы платите за сервер и тратите время на обновления, бэкапы и безопасность.

### Когда no-code платформы перестаёт хватать для интеграций?

Когда сценарии становится трудно понять, объём запусков делает оплату за шаг дорогой или процессу нужны строгие гарантии: порядок обработки, транзакции, подробные логи. Тогда надёжнее отдельный сервис интеграций на коде.
